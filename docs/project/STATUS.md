| 日期 | 决定 | 原因 | 影响 |
| --- | --- | --- | --- |
| 2026-07-29 | 批量生产为主，单商品创作台为辅 | 适配内部运营和每日大量生成 | 不做首版自由画布 |
| 2026-07-29 | 一 Agent 一会话，主 Agent 统一集成 | 保留角色上下文并防止决策分散 | 以本控制板为唯一事实来源 |
| 2026-07-29 | 运营前端采用 React + TypeScript + Vite | 创作台、拖拽、队列和审核需要可组合状态与高质量交互 | Django 保留为同源 API、Session、任务与后台；不引入 Next.js 或额外后端基础设施 |
| 2026-07-29 | 竞品图只用于抽象策略，不可作为生成参考 | 防止商品身份、版权与合规风险 | 原图仅可到批准的 `gpt-5-nano-2025-08-07` 视觉观察器；Prompt OS、前端生成请求和 `gpt-image-2` 均不得传递竞品图 |
| 2026-07-29 | 只有人工通过的版本可导出 | 区分技术完成和业务验收 | 导出 API、审核 UI 与 ZIP 规则需共同执行 |
| 2026-07-29 | APIMart API 活跃异步任务硬上限为 500 | 支撑目标吞吐，但不将供应商 API 上限误作当前服务器能力 | 运行默认仍为 2；按 2、5、8、50、100、250、500 分级压测，完成原子认领与限流后才能提高 |
| 2026-07-29 | 正式入口只要求账号登录，不使用来源 IP 白名单 | 内部员工从公网访问 | 仍必须使用域名 HTTPS、账号级失败锁定与首次改密，HTTP IP:端口只可做技术预览 |
| 2026-07-29 | 刘学城是唯一初始管理员 | 集中账号、规则与模板发布责任 | 管理员按名单创建运营账号；初始密码为英文小写姓名加 `123456` 并强制首次改密 |
| 2026-07-29 | 默认 8 张、1:1、1k，用户可从已发布允许项中调整 | 满足跨境商品页的首轮生产需求 | 规则模板按平台/市场决定槽位；TikTok 主图不叠加促销文字 |
| 2026-07-29 | 所有平台套图第 1 张固定为标准白底产品主图，并先完成再提交后续槽位 | 保证商品身份、上架基础质量与跨平台一致性 | 第 1 槽完整、真实、无促销文字/水印；同批次、同商品、同模板的后续 7 槽等待其完成，主图失败/取消时继续等待重做且不得调用供应商 |
| 2026-07-29 | 文字叠加按站点默认语言生成并人工审核 | 同时满足本地化和平台差异 | 主图与辅助图分槽；文本只能来自已证实商品事实 |
| 2026-07-29 | 闲时允许用户临时借用并发 | 在全局上限内提高资源利用率 | 基础每人 2 个活跃任务；有其他用户排队时恢复公平轮转 |
| 2026-07-29 | 竞品版式结构可作为 Style DNA 借鉴 | 满足同等商业视觉策略需求 | 可复用画面层级、版式、色彩、光线和场景密度；竞品原图仅发送给 `gpt-5-nano-2025-08-07` 观察器，不得传给生成、文本、Prompt 或导出链路，也不得复制商标、包装、人物、原文案及逐像素页面 |
| 2026-07-29 | 前端采用 A：商品生产工作台 | 当前功能页缺乏商品视觉、创作重心与品牌化登录首印象 | 新用户默认进入 SKU 导入创建，文件夹上传为补充；有进行中项目的用户默认进入生产总览。采用商品确认板、三栏创作台、人工审核闭环与选择式本地 ZIP 导出；不引入大型 UI 套件 |
| 2026-07-29 | 导出按通过版本、商品名称与 SKU 交付 | 员工需要可选择范围并放入自己的本地文件夹 | 只导出审核通过的最新版本；支持全选/筛选/选中商品/单商品/平台套图；ZIP 按“商品名称__SKU/01–08 槽位”组织，由浏览器保存窗口选择本地目录 |
| 2026-07-29 | 素材合并不等同于多角度 | 同款多色、花型、尺寸或款式是独立子 SKU，不可被自动合并 | 用户显式标记“同一可售 SKU 的补充参考”才合并；独立子 SKU 可归入商品家族并一键同时出图，但各自产出、审核和重做 |
| 2026-07-29 | SKU 是一等导入入口，图片上传保留为补充来源 | 运营已有商品资料系统，输入 SKU 即可取得商品名与产品图 | 服务端只消费输入 SKU、响应中的 `productName` 与 `pic`；SKU 保留为审计/重导入键，销售、库存、成本等字段不进入平台或 Prompt |
| 2026-07-29 | TXT 与 SKU 导入的文本框都是“种子风格提示词” | 普通运营不应编写完整生产 Prompt | 有内容时作为项目级风格偏好；为空时由营销图 Prompt 节点生成风格方案，仍不得虚构商品事实 |
| 2026-07-29 | 商品资料服务正式环境使用 .5 主机 16777 端口登录与查询 | SKU 导入需要由平台服务端安全获得授权后查询产品名和图片 | 账号、密码只进服务器 Secret；服务端登录取得 Token 并仅在进程内存保留，查询仅传 `skuList`，只消费 SKU、`productName`、`pic` |
| 2026-07-29 | Prompt OS 固定使用 APIMart 的 DeepSeek V4 Pro、GPT-5 Nano 视觉观察器与 GPT Image 2 | 让自动视觉理解可用，同时隔离竞品素材与生成链路 | `gpt-5-nano-2025-08-07` 只将我方源图、竞品图或生成候选图变为 Schema 校验的视觉事实包；`deepseek-v4-pro` 处理所有文本语义节点和结构化 Prompt；`gpt-image-2` 只生成/修订图片。竞品原图只到视觉观察器，绝不进入 DeepSeek、GPT Image 2、生产 Prompt、生成任务或导出。P0 必须以 APIMart 中文文档和账户验证三个精确模型 ID，失败时阻断而不降级 |
| 2026-07-29 | APIMart 视觉观察器首次真实契约成功，不等于质量通过 | 区分“接口可调用”与“商品视觉事实可靠” | 使用公开测试图的两次最小付费调用确认 `gpt-5-nano-2025-08-07`、`input_image` 和严格 JSON 路径可用；下一步须以带人工标注的商品基准集衡量事实准确率，未通过前不得作为自动审核结论 |
| 2026-07-29 | 首个实现切片只交付“SKU → 商品卡 → 8 槽计划 → 预检”的可演示闭环 | 先解决真实入口与确认生成前的事实完整性，避免并行改 Prompt Worker、审核和导出造成迁移冲突 | 不在首切片改真实生图提交、竞品 Style DNA、审核圈选或选择式导出；白底第 1 槽仍是模板中的硬前置。默认采用新模板版本，不改写已有项目的 4 槽快照 |
| 2026-07-29 | APIMart 的真实账号包络优先于文档示例 | 同一供应商不同模型端点的外层 JSON 已出现不一致，不能依赖单一伪造包络 | `deepseek-v4-pro` 账户实测为顶层 OpenAI Chat Completions 包络，非文档示例的 `code/data`；适配器必须按端点/模型显式解析并以真实 fixture 回归。GPT Image 2 已实测 `submitted → processing → completed`、结果 URL 与费用字段，完成后必须立即受限下载归档；`cancelled` 视为终态 |

## 更新协议

每次交接只更新相关任务行，并附：owner、目标、输入/输出契约、文件边界、验证命令/结果、状态、风险和下一个 owner。直接聊天得到的接口或需求决定，必须在同一工作回合回写到本文件或相应规格后才生效。跨 Agent 不得并行修改同一文件；只有主 Agent 可以合并任务或签核发布。
