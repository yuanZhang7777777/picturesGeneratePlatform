## 当前决定

| 日期 | 决定 | 原因 | 影响 |
| --- | --- | --- | --- |
| 2026-07-29 | 批量生产为主，单商品创作台为辅 | 适配内部运营和每日大量生成 | 不做首版自由画布 |
| 2026-07-29 | 一 Agent 一会话，主 Agent 统一集成 | 保留角色上下文并防止决策分散 | 以本控制板为唯一事实来源 |
| 2026-07-29 | 运营前端采用 React + TypeScript + Vite | 创作台、拖拽、队列和审核需要可组合状态与高质量交互 | Django 保留为同源 API、Session、任务与后台；不引入 Next.js 或额外后端基础设施 |
| 2026-07-29 | 竞品图只用于抽象策略，不可作为生成参考 | 防止商品身份、版权与合规风险 | Prompt OS、前端和供应商调用都不得传递竞品图 |
| 2026-07-29 | 只有人工通过的版本可导出 | 区分技术完成和业务验收 | 导出 API、审核 UI 与 ZIP 规则需共同执行 |
| 2026-07-29 | APIMart API 活跃异步任务硬上限为 500 | 支撑目标吞吐，但不将供应商 API 上限误作当前服务器能力 | 运行默认仍为 2；按 2、5、8、50、100、250、500 分级压测，完成原子认领与限流后才能提高 |
| 2026-07-29 | 正式入口只要求账号登录，不使用来源 IP 白名单 | 内部员工从公网访问 | 仍必须使用域名 HTTPS、账号级失败锁定与首次改密，HTTP IP:端口只可做技术预览 |
| 2026-07-29 | 刘学城是唯一初始管理员 | 集中账号、规则与模板发布责任 | 管理员按名单创建运营账号；初始密码为英文小写姓名加 `123456` 并强制首次改密 |
| 2026-07-29 | 默认 8 张、1:1、1k，用户可从已发布允许项中调整 | 满足跨境商品页的首轮生产需求 | 规则模板按平台/市场决定槽位；TikTok 主图不叠加促销文字 |
| 2026-07-29 | 所有平台套图第 1 张固定为标准白底产品主图，并先完成再提交后续槽位 | 保证商品身份、上架基础质量与跨平台一致性 | 第 1 槽完整、真实、无促销文字/水印；同批次、同商品、同模板的后续 7 槽等待其完成，主图失败/取消时继续等待重做且不得调用供应商 |
| 2026-07-29 | 文字叠加按站点默认语言生成并人工审核 | 同时满足本地化和平台差异 | 主图与辅助图分槽；文本只能来自已证实商品事实 |
| 2026-07-29 | 闲时允许用户临时借用并发 | 在全局上限内提高资源利用率 | 基础每人 2 个活跃任务；有其他用户排队时恢复公平轮转 |
| 2026-07-29 | 竞品版式结构可作为 Style DNA 借鉴 | 满足同等商业视觉策略需求 | 可复用画面层级、版式、色彩、光线和场景密度；不得上传竞品图给供应商或复制商标、包装、人物、原文案及逐像素页面 |
| 2026-07-29 | 前端采用 A：PhotoRoom 式商品生产画布 | 当前功能页缺乏商品视觉、创作重心与品牌化登录首印象 | 新用户默认进入文件夹上传创建；有进行中项目的用户默认进入生产总览。先重做认证入口、引导创建、SKU 分组板和商品创作台；不引入大型 UI 套件 |
| 2026-07-29 | 素材合并不等同于多角度 | 同款多色、花型、尺寸或款式是独立子 SKU，不可被自动合并 | 用户显式标记“同一可售 SKU 的补充参考”才合并；独立子 SKU 可归入商品家族并一键同时出图，但各自产出、审核和重做 |

## 更新协议

每次交接只更新相关任务行，并附：owner、目标、输入/输出契约、文件边界、验证命令/结果、状态、风险和下一个 owner。直接聊天得到的接口或需求决定，必须在同一工作回合回写到本文件或相应规格后才生效。跨 Agent 不得并行修改同一文件；只有主 Agent 可以合并任务或签核发布。
