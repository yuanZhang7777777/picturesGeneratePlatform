# Prompt OS 4.1 节点与营销生成设计

日期：2026-08-02
状态：GPT-5.5 下一轮唯一执行基线；尚未实现或发布
目标版本：`4.1.0`

## 1. 核心结论

4.1 不增加新节点。目标是把现有 N1–N9 真正连成一条可跑通、可追溯、少打扰运营的生产链路：

- `导入后整理`：只保存素材和商品卡，零 AI。
- `预备生成`：对选中商品跑 N1–N7，补空商品名，生成身份卡、事实台账和 1+8 Prompt，不生图。
- `正式生成`：如果当前商品没有 N7 通过的 Prompt，自动先预备，再继续白底和营销图生成。
- `导入并自动出图`：导入后自动跑同一条 N1–N7，再进入正式生成；识别不出的商品单独失败，其他商品继续。

默认配置固定为：`Shopee 虾皮 / 东南亚通用 / 1:1 / 1K`。国家只控制语言、硬规则和禁用内容，不限定场景。营销场景由商品事实、目标消费者、项目/单品风格提示词、Style DNA 和购买心理策略决定。

运营链路固定为两条，但底层只用一套节点：

1. `导入后整理`：只建商品卡，不识别、不策划、不生成。员工可以改名称、国家、补充资料、单品风格、缩略图顺序和卡片合并。
2. `导入并自动出图` / `正式生成`：如果没有当前配置对应的 N7 通过 Prompt，系统自动跑 N1–N7；能识别的商品继续生成，只有无法确认有效商品的卡片停下提示。

员工默认不看节点细节。只有点击“查看详情/高级编辑”时，右侧固定侧浮层展示商品身份、事实台账和 1+8 Prompt；侧浮层不挤压、重排或改变商品卡网格。

## 2. 一卡多图规则

一个商品卡是一套图的生产单元，不等于一个单一颜色或一个单一规格。

- 每张图默认一张商品卡。
- 图片拖入同一卡，表示这些图共同生成一套 1+8。
- 卡内图片可以是角度、细节、包装、配件，也可以是不同颜色、规格或款式。
- 第一张图片是主参考；点击缩略图只切换大图预览，拖动缩略图排序到第一位才改变主参考。
- N1 观察全部图片。
- N2 输出 `product_family` 和 `target_appearances`：同外观多角度归并，不同颜色/规格/款式拆成不同目标外观。
- 白底图和款式总览必须覆盖全部 `target_appearances`；其他营销图可以展示外观子集，但整套 1+8 必须覆盖所有外观。
- N6 给 GPT Image 2 的参考图默认使用“白底图 + 当前槽位需要的最少源图”，避免把所有原图背景都锚进每张营销图。
- 不给员工弹出“这是角度还是款式”的确认。AI 内部归并，归并不确定时按“保留为目标外观”处理，宁可让白底/总览多展示一个外观，也不阻断整套。
- 员工点击缩略图只是看大图；只有拖动排序才改变主参考。拖拽入口只放在缩略图条，避免员工想滚动页面时误拖整卡。

APIMart GPT Image 2 当前文档支持异步生成、`size`、`resolution` 和最多 16 张参考图。实际生产不默认塞满 16 张，只按槽位需要选择最少参考图。

## 3. 统一变量总线

后续节点只消费结构化变量，不重新猜图片关系。

```json
{
  "cluster_id": "uuid",
  "platform": "shopee",
  "country": "东南亚通用",
  "visible_text_policy": {
    "language": "English or local default",
    "allow_text": true,
    "max_lines": 3
  },
  "size": "1:1",
  "resolution": "1K",
  "project_style_prompt": "项目风格提示词",
  "product_style_prompt": "单品风格提示词；不为空时替代项目风格",
  "manual_product_name": "",
  "erp_product_name": "",
  "product_notes": "员工补充的材质、功能、消费者或特别要求",
  "assets": [
    {"asset_id": "a1", "order": 1, "role": "PRIMARY", "source": "upload"}
  ],
  "product_family": "",
  "shared_identity_lock": {},
  "target_appearances": [],
  "fact_ledger": [],
  "style_dna": null,
  "rule_snapshot": {}
}
```

人工填写名称、ERP 名称、SKU、补充资料都是 `confirmed`。AI 不得覆盖人工事实；空商品名由 N2 补全并标记为“AI 识别，可修改”。`string`、`image_role`、JSON、Schema、枚举差异等内部问题不得写进商品名或直接展示给员工。

前端中文字段使用：

- `国家`，不显示 `market`。
- `提示词` 或 `项目风格提示词`，不只写“项目风格”。
- 平台、国家、比例、分辨率同一行配置；比例和分辨率分开选择。

### 3.1 节点输入输出总表

| 节点 | 输入 | 输出 | 允许阻断 | 传给下一节点的关键变量 |
| --- | --- | --- | --- | --- |
| N1 逐图观察 | 单张图片、图片顺序、人工/ERP 名称、补充资料 | 可见商品证据、候选名称、图片角色、坏图原因 | 单图坏不阻断；全部图无有效商品才阻断商品 | `owned_observations[]`、`valid_asset_ids[]` |
| N2 身份归并 | 同一卡全部 N1、排序、人工/ERP 名称 | 商品展示名、共有身份锁、目标外观、主/辅参考图 | 全部无商品；人工名称与核心商品不可消解冲突 | `product_family`、`shared_identity_lock`、`target_appearances`、`primary_asset_id` |
| N3 事实台账 | N2、人工资料、补充资料、规则快照 | `confirmed/observed/inferred` 事实、风险和可用范围 | 高风险事实无法移除；事实与身份硬冲突 | `fact_ledger`、`allowed_fact_ids` |
| N4 白底编译 | N2/N3、目标外观、主/辅参考图、比例分辨率 | 白底 Prompt、白底参考图计划、禁止项 | 无我方参考图；白底硬规则无法满足 | `white_prompt_version`、`white_reference_plan` |
| N5 营销导演 | N2/N3、目标外观、规则、项目/单品提示词、Style DNA | 8 个购买任务、心理策略、场景、画面签名、外观覆盖计划 | 低质/重复先重写；仍无法覆盖外观或事实才阻断 | `slot_plans[]`、`appearance_coverage_plan` |
| N6 单槽编译 | 单槽 N5、N3、语言策略、白底结果、最少参考图 | 目标语言文案、中文回译、英文生图 Prompt、参考图选择 | 文案语言错、未知事实、超长且无法压缩 | `prompt_versions[]`、`localized_copy`、`reference_plan` |
| N7 规则闸门 | N6/N4 Prompt、事实、规则、引用、版本指纹 | `pass/block`、硬阻断、警告、一次低风险重写原因 | 技术不可提交和高风险可见内容；其他只提示审核 | `n7_pass_snapshot` |
| N8 修改导演 | 圈选、审核意见、原图、原 Prompt、身份锁 | 最小差量 Prompt | 修改违反身份锁或硬规则 | `revision_prompt_version` |
| N9 失败简化 | 可简化失败、原 Prompt、身份锁、规则 | 更短等价 Prompt 或人工修改要求 | 网络/限流/余额/未知提交状态不处理 | `simplified_prompt_version` |

执行者实现时优先保证这张表可被测试验证。缺少表中关键变量时，后续节点不得用旧值、空字符串或 `builtin-v1` 兜底继续生成。

### 3.2 付费生成前唯一门禁

任何入口最终都必须走同一个提交验证器。它只回答一个问题：当前这张待生成图片是否可以花钱提交给 `gpt-image-2`。

允许提交必须同时满足：

```text
当前商品版本未过期
+ 当前平台/国家/比例/分辨率指纹未过期
+ 当前 N2 target_appearances 存在且引用当前资产
+ 当前槽位有 N4 或 N6 PromptVersion
+ 当前槽位有同一输入指纹的 N7 pass 快照
+ 最终 image_urls 只包含 N2 批准的我方参考图或本商品白底结果
+ 营销槽位的白底门禁已完成
```

任一条件不满足：

- `导入后整理`：继续停在商品卡，不自动调用 AI。
- `预备生成`：只阻断当前商品，并显示业务化原因。
- `正式生成`：如果只是 Prompt 缺失或过期，自动排队预备；如果是平台建议、文案质量、普通语言风险或身份不完整，继续出图并进入人工复核提示；只有无可用我方参考、竞品图误入参考、Prompt 超长、版本过期或高风险可见内容才阻断当前商品。

员工界面只显示可行动错误：`请换一张更清楚的商品图`、`请补充商品名称或用途`、`登录已过期，请重新登录`、`系统识别异常，请重试预备生成`、`平台规则不允许这张图生成`。不得显示 `image_role`、`visible product identity`、JSON、Schema、字段名或模型原文。

### 3.3 节点失败归一化

节点失败先按业务处理，不直接当成“用户图片不行”。执行者要把失败分成四类，按下表处理：

| 类型 | 例子 | 系统动作 | 员工看到 |
| --- | --- | --- | --- |
| 可归一化模型输出 | `string`、字段别名、`product_detail`、枚举大小写差异 | 清理或映射一次，继续当前商品 | 不提示 |
| 单图无效 | 空白图、严重模糊、非商品图 | 标记该图无效；同一卡还有有效图就继续 | 只在详情里提示“有图片未参与识别” |
| 商品级业务阻断 | 同一卡全部图片都无商品；人工名称和图片核心商品明显冲突；高风险事实无法移除 | 只阻断当前商品，其他商品继续 | 换更清楚商品图、改商品名或补充用途 |
| 系统/供应商问题 | JSON 修复失败、模型超时、限流、余额、提交状态未知 | 当前商品进入可重试状态；网络/限流不走 N9 | 系统识别异常、稍后重试或联系管理员 |

这张表是实现门禁。`image_role must...`、`visible product identity cannot...`、Schema、JSON、字段名、英文模型原文不能进入普通员工界面；它们只能进日志、Prompt 快照或管理员排障信息。

## 4. 九节点设计

### 4.0 每个节点模板的硬结构

4.1 的重点不是把 system prompt 写得更长，而是每个节点都必须有同一套可执行骨架。执行者改模板时不能只写“你是某某专家”。

每个节点模板必须按下面顺序包含六段：

1. `角色与唯一职责`：本节点只做什么，不做什么。
2. `输入变量解释`：逐项解释运行时输入键，尤其是 `target_appearances`、`fact_ledger`、`style_dna` 和 `localized_copy`。
3. `决策规则`：哪些情况继续、重写、阻断；能继续就继续。
4. `质量评分`：用结构化字段判断结果是否够用，而不是靠一句“更好看”。
5. `输出 JSON Schema 约束`：禁止 Markdown、禁止额外字段、禁止示例值 `string`。
6. `失败归一化`：模型字段错误内部处理，不直接给员工看。

每个节点的 system prompt 可以长；`3500` 字符限制只作用于最终提交给 GPT Image 2 的单图 `final_english_image_prompt`。

### 4.0.1 节点模板不是职责摘要

5.5 执行时检查真实 `system_prompt`，不是检查文档段落。每个节点模板至少要能回答：

- 本节点读哪些变量，哪些变量只读不能改。
- 本节点产出哪些变量，后续哪个节点消费。
- 哪些问题内部归一化，哪些问题阻断。
- 本节点如何评分“够不够好”。
- 如果模型返回示例值、空话、重复文案或字段别名，代码如何修复一次或阻断。

如果模板只有“你是营销导演，请输出 JSON”这种短摘要，视为未实现 4.1。

### 4.0.2 GPT-5.5 执行用最终节点蓝图

本节是执行 Agent 写代码和模板时的最短判定标准。实现时不要再发明新节点，也不要把节点写成更复杂的审核流。能继续就继续；只有技术不可提交、高风险可见内容、安全风险或历史覆盖时才阻断当前商品。

| 节点 | 本节点只做什么 | 必须读取 | 必须产出 | 继续/阻断边界 |
| --- | --- | --- | --- | --- |
| N1 逐图观察 | 把每张我方图变成可见证据 | 当前商品全部图片、排序、人工/ERP 名称、补充资料 | `owned_observations[]`、`valid_asset_ids[]`、候选名称、图片角色 | 单图坏继续；全部图无商品才阻断 |
| N2 商品家族与外观 | 把一卡多图整理成一套图的身份变量 | N1 全部结果、排序、人工/ERP 名称 | `product_family`、`shared_identity_lock`、`target_appearances`、主/辅参考图 | 多色/多款不是冲突；名称与实物核心冲突才阻断 |
| N3 事实台账 | 区分确认事实、观察事实和推断 | N2、人工资料、规则快照 | `fact_ledger[]`、可用 `fact_id`、风险和允许用途 | 事实少不阻断；高风险事实进入文案才阻断 |
| N4 白底编译 | 写标准白底图 Prompt | N2/N3、目标外观、参考图、尺寸 | 白底 Prompt、白底参考图计划、禁止项 | 无我方参考图或白底规则无法满足才阻断 |
| N5 营销导演 | 把商品事实转成八张购买任务 | N2/N3、风格提示词、Style DNA、平台/国家 | `slot_plans[]`、`copywriting_chain`、`appearance_coverage_plan` | 低质/重复先重写；仍不能覆盖外观/事实才阻断 |
| N6 单槽编译 | 写目标语言文案和英文生图 Prompt | 单槽 N5、事实、语言、规则、白底结果 | `localized_copy`、三候选评分、`final_english_image_prompt`、参考图计划 | 语言错、事实错、文字锁错或超长无法压缩才阻断 |
| N7 规则闸门 | 付费前最后一次确认能不能提交 | N4/N6 Prompt、事实、规则、引用、指纹 | `n7_pass_snapshot` 或业务化阻断原因 | 只阻断技术不可提交和高风险可见内容；其他问题进审核提示 |
| N8 修改导演 | 把圈选反馈变成最小差量 | 原图版本、圈选、审核说明、身份锁 | 差量 Prompt、保留项、规则引用 | 修改会破坏身份/规则才阻断 |
| N9 失败简化 | 只压缩可安全重写的 Prompt | 失败分类、原 Prompt、身份锁、规则 | 更短等价 Prompt 或人工修改要求 | 网络、余额、限流、未知提交状态不处理 |

#### 节点变量交接线

执行时只能沿这一条变量线往下传，不允许某个节点缺值后用旧 Prompt、空对象、`string` 或 `builtin-v1` 补洞：

```text
N1 owned_observations / valid_asset_ids
→ N2 product_family / shared_identity_lock / target_appearances / primary_asset_id
→ N3 fact_ledger / allowed_fact_ids
→ N4 white_prompt_version / white_reference_plan
→ N5 slot_plans / appearance_coverage_plan / copywriting_chain
→ N6 localized_copy / final_english_image_prompt / reference_plan
→ N7 n7_pass_snapshot
→ Generation
```

#### 运行时调用格式

5.5 执行 Agent 必须把每个节点实现成同一种调用形状，方便排错和复用。不要为每个节点临时拼不同字段名。

```json
{
  "node": "N5.shopee",
  "prompt_os_version": "4.1.0",
  "model": "deepseek-v4-pro",
  "temperature": 1.6,
  "input_fingerprint": "hash of product version + config + assets + upstream node versions",
  "system_prompt_version": "4.1.0",
  "input": {},
  "expected_schema": {},
  "output": {},
  "normalized_output": {},
  "quality": {
    "passed": true,
    "scores": {},
    "warnings": [],
    "blockers": []
  }
}
```

每个节点都要保存 `input`、`output`、`normalized_output` 和 `quality` 到不可变快照。下游只能读取 `normalized_output`，不能直接读模型原始输出。模型原始输出里出现 `string`、字段别名、大小写差异、Markdown 包裹、Schema 示例值时，只允许当前节点归一化一次。

#### 节点模型与温度

| 节点 | 模型 | 温度 | 原因 |
| --- | --- | --- | --- |
| N1 | `gpt-5-nano-2025-08-07` | 低温 | 只做图像观察，减少臆测 |
| N2 | `deepseek-v4-pro` | 0.3 | 身份归并需要稳定 |
| N3 | `deepseek-v4-pro` | 0.2 | 事实和风险分类不能发散 |
| N4 | `deepseek-v4-pro` | 0.4 | 白底图需要清晰稳定 |
| N5 | `deepseek-v4-pro` | 1.6 | 营销策划需要创意发散 |
| N6 | `deepseek-v4-pro` | 1.0 | 文案需要有吸引力但仍可控 |
| N7 | `deepseek-v4-pro` + 确定性规则 | 0.2 | 付费前门禁必须稳定 |
| N8 | `deepseek-v4-pro` | 0.4 | 圈选修改要精确 |
| N9 | `deepseek-v4-pro` | 0.2 | 失败简化要等价保守 |

温度可由服务器环境覆盖，但执行计划和测试必须先按上表验证。不要为了让测试过而把 N5/N6 降成低温短模板。

#### 统一提示词骨架

每个真实 `system_prompt` 都必须包含以下六段，且内容必须写到可执行粒度：

```text
1. 角色与唯一职责：本节点只负责什么，明确不负责什么。
2. 输入变量解释：逐项解释运行时 JSON，哪些字段只读，哪些字段可改。
3. 决策规则：继续、重写、阻断的边界；默认能继续就继续。
4. 质量评分：输出哪些分数或检查字段，什么值算合格。
5. 输出 JSON Schema 约束：禁止 Markdown，禁止额外字段，禁止示例值 string。
6. 失败归一化：字段别名、大小写、示例值、轻微缺字段如何修复一次；员工看什么中文错误。
```

节点提示词可以长。`3500` 字符只限制 N6 最终传给 `gpt-image-2` 的单张 `final_english_image_prompt`，不限制节点 system prompt。

#### 普通员工错误边界

下列内容只能进日志、管理员排障或节点快照，不能给员工看：`image_role`、`visible product identity`、JSON、Schema、字段名、英文模型原文、`string`。

员工只看五类中文结果：

1. `AI 正在识别 / Prompt 生成中 / 正在生成`。
2. `请换一张更清楚的商品图`。
3. `请补充商品名称或用途`。
4. `登录已过期，请重新登录`。
5. `系统识别异常，请重试预备生成`。

如果同一卡还有至少一张有效商品图，N1/N2 不得因为某张坏图、字段别名或模型枚举不一致阻断整卡。

### N1 逐图观察

- 模型：`gpt-5-nano-2025-08-07`
- 温度：低温
- 输入：单张我方图片、图片顺序、人工/ERP 名称、员工补充资料。
- 输出：候选商品名、可见商品、部件、颜色、数量、包装、配件、人物/道具、图片角色、置信度。
- 关键要求：只描述看见的东西，不推断材质认证、疗效、价格或品牌。只要图中有可售商品，即使不是白底图，也识别为我方商品参考。
- 失败边界：单图坏只标记坏图；全部图片都没有有效商品才阻断商品卡。
- 归一化要求：`product`、`main_product`、`hero`、`detail`、`packaging` 等模型同义角色要映射为内部允许角色；不得把 `image_role must...` 这种技术失败展示给员工。

N1 system prompt 必须包含：

```text
你是跨境电商商品图观察员。只观察我方上传图片。输出严格 JSON。
不要把示例值 string 当结果。不要把背景道具当商品。
如果图片中有可销售商品，即使不是白底图，也要识别为 owned product reference。
不要判断平台合规，不要写营销文案，不要推断未看见的材质、认证、价格、功效。
```

### N2 商品家族与目标外观

- 模型：`deepseek-v4-pro`
- 温度：0.3
- 输入：同一卡全部 N1 结果、图片顺序、人工/ERP 名称、补充资料。
- 输出：展示商品名、`product_family`、`shared_identity_lock`、`target_appearances`、主/辅参考图、冲突状态。
- 关键要求：同一卡可以包含多色、多规格、多款。不要强行压成单一外观，也不要要求员工维护“多图关系”。
- 失败边界：全部无有效商品，或手填名称与图片核心商品明显冲突且无法继续。
- 决策原则：能继续就继续。只有核心商品完全无法判断时阻断；多色/多款不属于冲突，而是 `target_appearances`。

`target_appearances` 必须至少包含：

```json
{
  "appearance_id": "appearance.001",
  "label": "浅木色餐具套装",
  "asset_ids": ["asset_1", "asset_2"],
  "appearance_type": "main | color_variant | size_variant | style_variant | package_or_accessory",
  "visible_traits": ["浅木色", "筷子", "勺子", "收纳盒"],
  "must_show_in": ["white_background", "overview_or_contents"],
  "can_show_in": ["benefit", "detail", "usage"]
}
```

### N3 事实台账

- 模型：`deepseek-v4-pro`
- 温度：0.2
- 输入：N2、人工/ERP 资料、补充资料、平台国家、规则快照。
- 输出：`confirmed / observed / inferred` 三类事实，含 `fact_id`、证据、置信度、风险、允许用途。
- 关键要求：能进入图片可见文案的事实必须有 `fact_id`。高风险内容默认不能进入文案。
- 失败边界：事实少不阻断；只有事实与身份严重冲突或高风险声明无法移除时阻断。

禁止仅靠推断进入画面的内容：价格、促销、认证、医疗/美容/减重功效、夸张安全承诺、站外联系方式、未授权 IP。

### N4 标准白底编译

- 模型：`deepseek-v4-pro`
- 温度：0.4
- 输入：身份锁、目标外观、主图、必要辅助图、尺寸、规则。
- 输出：英文白底图 Prompt、参考图计划、禁止项。
- 关键要求：白底图不是营销图。无新增文字、无水印、无道具、无背景场景。多色/多款组合要清楚展示全部目标外观。
- 失败边界：无可用我方参考图、竞品图误入参考、Prompt 超长或高风险可见内容；平台图片建议不阻断预览生产。

### N5 八图营销导演

- 模型：`deepseek-v4-pro`
- 温度：1.6
- 输入：N2/N3、目标外观、平台国家、项目/单品风格提示词、Style DNA、营销槽。
- 输出：每槽中文策划，不输出最终图片 Prompt。
- 关键要求：N5 要决定每张图为什么存在，而不是把商品功能换个说法。

N5 必须先发散再收敛：每槽至少内部比较真实使用、问题解决、细节信任、尺度适配、夸张广告道具、情绪化空间或类目隐喻等不同视觉方案，再选择最能把商品事实变成购买理由的一种。国家只控制语言和规则，不把场景写死成某个国家住宅、桌面摆拍或固定动作。

N5 内置五种购买心理策略：

1. `fab_value`：商品事实 → 优势 → 用户收益。文案是商品卖点的翻译官。
2. `scene_ownership`：让用户脑内出现“我正在使用它”的画面。
3. `emotion_shift`：把麻烦、尴尬、不安转成轻松、安心、体面。
4. `personification`：让商品用自然口吻跟消费者说一句话；默认最多一张。
5. `identity_signal`：让商品代表审美、身份、品位或生活方式。

八张营销图至少覆盖四种策略，必须至少一张 FAB，拟人默认最多一张。策略不是固定槽位，N5 根据商品和购买任务动态分配。

N5 的核心不是“写标题”，而是先翻译购买理由：

```text
商品事实 fact_refs
→ 用户任务 user_job：用户为什么会需要它
→ 心理触发 strategy_mode：省事、安心、体面、占有、身份
→ 场景画面 scene_brief：一眼看懂的生活瞬间
→ 文案意图 copy_intent：让用户产生什么购买念头
→ 画面签名 composition_signature：防止八张图重复
```

N5 不是一个单句“营销大师”节点，而是四步内部链路：

1. `buyer_insight`：从商品名称、图片和补充资料里找买家真正关心的使用任务、顾虑、尴尬点、送礼/自用动机。
2. `scene_director`：把动机变成画面事件、人物/手/宠物/空间关系、镜头、光线、道具层次；不按国家写死场景。
3. `copy_strategy`：按 FAB、场景占有、情绪触发、拟人表达或身份表达，决定这张图该说什么，不直接生成最终文字。
4. `set_diversity`：检查八张图的购买问题、构图、动作、场景密度和文字策略不要重复。

N6 再把 `copy_strategy` 翻成目标国家语言的短文案，并把 `scene_director` 翻成可直接给 `gpt-image-2` 的英文画面 Prompt。这样营销创意和本地化各自独立，避免一个节点既想场景又翻译又写生图指令，最后全部变成 AI 味短句。

五种策略的使用方式：

| 策略 | 适合场景 | 输出重点 | 禁止写法 |
| --- | --- | --- | --- |
| `fab_value` | 商品有清晰结构、功能、套装、材质线索 | 把“商品有什么”翻译成“用户少了什么麻烦/多了什么结果” | 只列功能词，如“高弹、耐用、便携” |
| `scene_ownership` | 使用动作明确的商品 | 让用户看见自己正在使用，产生占有感 | 空泛生活方式照 |
| `emotion_shift` | 能解决尴尬、脏乱、费力、不安的商品 | 前后情绪变化，但不做夸大前后对比 | 恐吓、羞辱、过度焦虑 |
| `personification` | 商品有可爱、亲切、礼物、家居属性 | 用商品口吻说一句自然短句 | 每张都拟人，或说出虚假事实 |
| `identity_signal` | 装饰、穿戴、礼品、家居审美类商品 | 让商品代表审美、品位或生活方式选择 | “高端身份”“贵族感”等空洞词 |

N5 只产出策划和文案意图，不产出最终图片文字。最终可见文字必须由 N6 按目标语言重新创作并自检。这样避免中文视频文案方法直接变成别扭翻译，也避免在 N5 把没有事实证据的卖点写死。

N5 不受国家场景限制。国家只传入语言、禁字和硬规则；例如越南站可以出现现代厨房、宿舍、办公室、宠物角、浴室、户外桌面等，只要商品和消费者关系成立。

每槽必须输出：

```json
{
  "slot_order": 3,
  "slot_name_zh": "核心卖点图",
  "appearance_ids": ["appearance.001"],
  "strategy_mode": "fab_value",
  "user_job": "用户想解决的真实任务",
  "value_translation": "把商品事实翻译成用户收益",
  "scene_brief": "一个清晰、有画面感的场景",
  "emotional_trigger": "触发的情绪或占有欲",
  "composition_signature": "scene|camera|action|layout",
  "copy_intent": "可见文案要完成的心理动作",
  "fact_refs": ["fact.name.001"]
}
```

禁止空泛成品文案：`品质生活`、`高级感`、`理想之选`、`Premium quality`、`Perfect for every moment`、`Easy to use`。这些只能作为坏例子，不得作为最终文案。

N5 还必须输出一条可追踪的“购买冲动转换链”，否则后续 N6 容易退回空泛短句：

```json
{
  "copywriting_chain": {
    "raw_fact": "商品事实，不可虚构",
    "feature": "商品有什么",
    "advantage": "相比普通选择好在哪里",
    "user_benefit": "用户得到什么结果或少掉什么麻烦",
    "ownership_moment": "用户脑中出现的使用画面",
    "emotion_hook": "触发安心、体面、轻松、占有或惊喜",
    "copy_angle": "本槽文案应从哪个角度说服用户",
    "risk_note": "是否可能夸大、虚构或触碰平台禁区"
  }
}
```

示例逻辑只作为方法，不作为固定文案：

- 不写“高弹面料”，而写“深蹲不尴尬”这类用户结果；前提是事实台账确实允许引用弹力和遮挡能力。
- 不写“轻巧便携”，而写“包里多塞一个也不累”这类使用画面；前提是商品确实可携带。
- 不写“高级审美”，而把商品放入更具体的身份选择，例如“餐桌看起来更会招待客人”；前提是商品属于家居/餐具/装饰等合适场景。

如果证据不足，N5 仍然可以有创意，但只能创意化场景、镜头、情绪和表达方式，不能创意化商品事实。

### N6 单槽本地化文案与生图编译

- 模型：`deepseek-v4-pro`
- 温度：1.0
- 输入：单槽 N5、N3 事实、目标语言、规则、白底图、必要参考图。
- 输出：目标语言可见文案、中文回译、自检、英文 `final_english_image_prompt`、参考图选择。
- 关键要求：图片上可见文字直接用目标语言创作，不先写中文再逐字翻译。给 GPT Image 2 的画面控制必须英文；目标语言文字逐行锁定，图片模型不得翻译、改写、增删。

N6 还必须输出运营可编辑的 `display_prompt`：它是完整正向中文广告图导演稿，不是“画面/主体/动作/构图”字段摘要，也不是防错清单。内容要像真正给图片模型的提示词，写清画面内容、商品呈现、人物/空间关系、镜头构图、光线、材质、色彩、版式文字和购买情绪。负向清单、错误示例和平台风险留给内部校验与 N7，不进入运营可见图片提示词；文字版式用正向设计描述，不写“文字不遮挡/预留安全区”。

每槽必须输出：

```json
{
  "visible_text_lines": ["Keep lunch tidy"],
  "localized_copy": {
    "language": "English",
    "lines": ["Keep lunch tidy"],
    "back_translation_zh": ["让午餐收纳更整齐"],
    "tone": "clear, useful, not generic",
    "source_fact_refs": ["fact.name.001"],
    "fluency_score": 4,
    "ambiguity_risk": "low"
  },
  "final_english_image_prompt": "Create a 1:1 ecommerce product image... Visible text: render exactly these lines with no translation, no extra words: \"Keep lunch tidy\" ...",
  "reference_plan": {
    "use_white_background_result": true,
    "source_asset_ids": ["asset_1"],
    "reason": "needed for appearance.001 structure"
  }
}
```

最终英文 Prompt 必须包含：主体身份锁、目标外观、一个主场景、一个主要动作、构图/镜头、光线/质感、道具、可见文案逐行锁定、参考图计划、禁止项。单图 Prompt 不超过 3500 字符。

最终传给 GPT Image 2 的 Prompt 使用固定骨架，禁止把节点分析全文塞进去：

```text
Use the attached approved product references only.
Product identity to preserve: ...
Target appearance(s) in this image: ...
Create one ecommerce listing image for: <slot_name_zh>.
Scene: one clear scene...
Main action: one action or none...
Composition and camera: ...
Lighting/material/style anchors: ...
Visible text: render exactly these lines, do not translate, do not add extra words:
"..."
Negative constraints: no extra text, no watermark, no fake logo, no price, no unsupported claims...
```

如果目标国家语言为英语，`visible_text_lines` 直接是英文；如果是泰语、越南语、繁体中文等，英文 Prompt 中仍原样嵌入目标语言文本，并要求图片模型逐字渲染。

N6 的文案生成必须先做三候选自评，再选择一条进入最终 Prompt。候选不展示给普通员工，但要进快照，便于以后排查为什么文案差：

```json
{
  "copy_candidates": [
    {
      "lines": ["..."],
      "back_translation_zh": ["..."],
      "purchase_pull_score": 4,
      "fluency_score": 5,
      "scene_fit_score": 4,
      "fact_safety_score": 5,
      "reason": "为什么选或不选"
    }
  ],
  "selected_candidate_index": 0
}
```

选择规则固定为：先排除事实风险和语言不顺，再选购买冲动最强、场景最贴合的一条。不得因为“短”就选空泛句。

### N7 规则闸门

- 执行器：确定性规则 + `deepseek-v4-pro` 语义补充
- 温度：0.2
- 输入：N6 Prompt、可见文案、事实引用、规则快照、参考图计划、版本指纹。
- 输出：`pass/block`、硬阻断、警告、一次重写原因。
- 硬阻断：无当前 Prompt/版本过期、竞品图进入参考、无可用我方参考图、Prompt 超长、价格/折扣、认证/奖项、医疗/疗效、100%/绝对承诺、站外导流、未授权 IP、危险/色情/暴力/仇恨/儿童安全。
- 自动重写：只允许空泛/重复/语言不顺这类低风险文案问题，且只重写当前槽一次。

员工不应看到 `image_role`、JSON、Schema、`visible product identity`、字段名等内部错误。内部技术问题统一显示“系统识别异常，请重试预备生成”。员工只看到可行动错误：换图、修改名称、补充资料、重新登录、稍后重试。

N7 不是“为了检查而检查”。当前预览生产采用宽门禁：平台差异、文案质量、普通语言问题、身份不完整和构图风险默认只进人工复核提示，不阻断出图。阻断只分三类：

1. 技术不可提交：无当前 Prompt、版本过期、无可用我方参考图、竞品图误入参考、Prompt 超长。
2. 高风险可见内容：价格/折扣、认证/奖项、医疗/疗效、减重/美容前后、100%/绝对承诺、站外导流、未授权 IP。
3. 安全风险：危险、色情、暴力、仇恨、儿童安全等会影响账号或合规底线的内容。

空泛、重复、不够顺、目标语言不够自然、平台图片建议未完全满足、商品身份卡不够完整，都只触发当前槽 N6 一次重写或进入人工复核提示，不影响其他商品继续。

### N8 审核修改导演

- 模型：`deepseek-v4-pro`
- 温度：0.4
- 输入：圈选坐标、问题标签、审核说明、原图版本、原 Prompt、身份锁、规则。
- 输出：只改目标区域的差量 Prompt。
- 关键要求：不重写整张图，不改变未圈选区域。若 APIMart 不支持精确 Mask，就生成受控标注参考图，不伪装成像素级 Mask。

### N9 失败简化

- 模型：`deepseek-v4-pro`
- 温度：0.2
- 输入：被拒 Prompt、失败分类、身份锁、规则。
- 输出：更短但事实等价的 Prompt。
- 只处理：Prompt 复杂度、允许重写的内容安全失败。
- 不处理：网络、余额、限流、未知提交状态。这些直接走重试或运维提示。

## 5. 工作台体验边界

工作台只保留运营高频动作，避免把节点复杂度暴露给员工：

- 顶部配置一行展示：平台、国家、比例、分辨率、项目风格提示词；项目名放左上，不占配置主体空间。
- 图片/文件夹与 ERP SKU 同屏放在一个常驻导入区；选择图片/文件夹按钮放在拖拽区内，导入后整理和自动出图按钮放在导入区底部。
- 商品卡目标是一行约 5 张。卡片主图使用 `object-contain`，不裁掉商品全貌。
- 多图商品卡展示一张大图 + 下方横向真实缩略图；缩略图溢出才横向滚动。
- 点击缩略图切换大图预览；拖动缩略图排序；跨卡拖缩略图合并；拖到空白处拆成新卡。
- 预备/正式生成按钮必须在长列表滚动时仍容易点击：桌面端使用右下角固定操作条，显示“已选 N / 预备生成 / 正式生成 / 生产结果”。
- 预备生成必须有脉冲进度：`N1 2/6`、`N6 4/8` 这种业务状态，不显示模型字段名。
- 预备阶段右侧浮层只展示“是什么图 + Prompt 是什么”，不展示未生成的图片预览占位图。
- 商品身份卡和 Prompt 在浮层内可直接编辑；改完点击“重新生成 Prompt”，不需要另一个“保存修改”心智。

## 6. 1+8 套图职责

1. 标准白底产品图：看清商品和全部关键外观。
2. 第二视角/结构图：补主图看不到的结构关系。
3. 核心卖点图：把最强事实翻译成用户收益。
4. 商品细节图：质感、接口、纹理、做工、包装细节。
5. 功能说明图：展示正确使用关系，不夸大。
6. 使用场景图：让用户产生“我正在用”的画面。
7. 模特/比例/适配图：按真实消费者适配人、宠物、儿童或空间比例。
8. 尺寸/包装/内容物图：解释套装、规格、包含物或多色多款。
9. 购买收尾图：用情绪、身份或生活方式完成转化。

槽位名称在前端全部显示中文，不显示 `Standard white-background product hero` 这类英文内部名。

## 7. Style DNA 使用方式

用户提供的优秀 Prompt 样例不作为商品事实，只拆成可复用 Style DNA：

- `style_fidelity_anchors`：光线、镜头、层次、材质、画面密度。
- `composition`：主体位置、深度层、图文层级。
- `typography`：字体气质、标题/小字/徽章/弧形呼号。
- `color_palette`：主色、辅助色、强调色、冷暖关系。
- `photographic_direction`：光线、镜头、质感、商业成片风格。
- `source_content_to_avoid`：原品牌、原商品、原故事、原文案、原布局、Logo、QR、水印。

Style DNA 只影响画面语言和视觉张力，不新增事实，不复制第三方商品、品牌、人物、原文案、可识别版式或源故事。

Style DNA 转成 N6 Prompt 时必须拆成原子变量，不得整段塞入最终 Prompt：

```json
{
  "style_atoms": {
    "scene_energy": "fresh / cozy / premium / playful / practical",
    "lighting": "sunlit / soft studio / clean daylight",
    "composition": "hero product front third, layered depth, readable copy zones",
    "typography": "short headline, small support copy, optional badge",
    "color_palette": "dominant/support/accent colors",
    "props": "only props that fit the product and do not imply unsupported facts",
    "avoid": "source brand, copied layout, copied slogan, QR, watermark"
  }
}
```

最终 GPT Image 2 Prompt 只引用当前槽需要的 style atoms。密集海报风格可以用于营销图，但白底图不能套用海报、徽章或广告文字。
