# Prompt OS 3.1 营销文案与创意场景设计

日期：2026-08-02

状态：已确认设计，等待执行 Agent 实现

基线：Prompt OS `3.0.0` 继续运行；本设计目标版本为 `3.1.0`

## 1. 目标

把现有“描述商品、安排八个不同场景”升级为“从商品事实出发，设计八个不同购买理由，并写出能让消费者想象拥有后体验的图片文案”。

本轮不增加第十个节点、不增加数据表、不改变人工审核与平台规则边界。N1–N4 负责看清商品和守住事实，N5 决定每张图为什么能打动人，N6 写目标语言短文案并编译英文图片指令，N7 在付费生成前完成事实、语言、重复度和平台规则检查。

## 2. 设计原则

1. **先事实，后创意。** 商品名称只是线索，最终可用卖点必须来自 N3 事实台账；没有商品名但图片可识别时正常生成。
2. **先用户结果，后功能名称。** 不写“高弹、便携、优质”，先回答它具体替用户解决什么、在哪一刻发生。
3. **先购买任务，后画面装饰。** 场景、人物、道具、文案必须共同服务一个购买问题。
4. **一张图只打一个点。** 每槽只有一个主策略、一个主场景、一个主动作和一个文案区域。
5. **创意不等于编造。** 场景和情绪可以发散；参数、认证、效果、材质、价格、促销和功能不能凭空补。
6. **国家只管语言与硬规则。** 不用国旗、地标、民族服饰或刻板人物替代真正的商品创意。
7. **文字先定稿再生图。** N6 直接以目标市场语言创作并自检；最终英文图片 Prompt 逐字锁定本地化文案。
8. **低质量自动修复，不打扰员工。** 技术 Schema、空泛文案、重复角度先在当前节点重写一次；只有全部图片无有效商品或存在硬规则冲突才要求员工处理。

## 3. 九节点最终职责

| 节点 | 模型/执行器 | 核心输入 | 必须输出 | 允许阻断的情况 |
| --- | --- | --- | --- | --- |
| N1 逐图观察 | `gpt-5-nano-2025-08-07` | 当前商品全部我方图片；逐张调用 | 图片角色、可见商品、候选名称、结构/颜色/数量、使用关系、质量 | 图片不可读或该图没有商品；单图失败不能阻断其他有效图 |
| N2 身份归并 | `deepseek-v4-pro` | 全部 N1 观察、员工/ERP 名称、图片顺序 | 商品家族、共有身份锁、主参考、辅助参考、`target_appearances` | 全部图片均无有效商品；有效图存在时不得因枚举/占位词/低置信名称阻断 |
| N3 事实台账 | `deepseek-v4-pro` | N2、员工补充、观察证据 | `confirmed/observed/inferred`、证据、风险、允许用途、禁用 claims | 高风险冲突无法隔离；普通缺失信息进入未解决项而非阻断 |
| N4 白底编译 | `deepseek-v4-pro` | 身份锁、外观、事实、白底规则 | 英文白底 Prompt、全部外观覆盖、最少参考图、事实引用 | 身份/数量/参考图缺失或白底硬规则冲突 |
| N5 营销导演 | `deepseek-v4-pro` | N2/N3、目标消费者、八个营销槽、项目/单品风格、平台/国家 | 每槽购买任务、创意策略、场景、画面心理、文案意图、外观覆盖 | Schema 修复后仍缺槽、事实引用无效或八图严重重复 |
| N6 本地化编译 | `deepseek-v4-pro` | 单槽 N5 计划、事实、身份、语言、规则、Style DNA | 目标语言短文案、文案质量记录、英文 `gpt-image-2` Prompt、参考计划 | 本地化仍歧义、文字与事实不符、锁定文字无法建立 |
| N7 生成前闸门 | 后端确定性检查 + `deepseek-v4-pro` | N6 结构化文案、最终 Prompt、规则/事实/参考/版本快照 | `pass/block`、硬阻断、自动重写原因、警告、完整检查值 | 平台/安全硬规则、事实幻觉、文字锁不一致、引用/版本过期 |
| N8 修改导演 | `deepseek-v4-pro` | 圈选、问题标签、文字反馈、原 Prompt/身份/规则 | 只改目标区域的差量英文 Prompt、完整锁定文案 | 用户要求改变商品身份或绕过硬规则 |
| N9 失败简化 | `deepseek-v4-pro` | 可简化失败、原 Prompt、身份/事实/文字/规则 | 更短但事实等价的英文 Prompt | 网络、限流、权限、余额、硬安全失败不得改写重试 |

## 4. N5 的五种营销策略

五种策略是候选池，不是固定槽位，也不是从低到高每图各写一次。

| 模式 | 要解决的问题 | 文案转换公式 | 合适画面 |
| --- | --- | --- | --- |
| `fab_value` | 用户不理解功能和自己有什么关系 | Feature → Advantage → Benefit | 问题/解决、结构证据、正确使用结果 |
| `scene_ownership` | 用户还没产生“这是我的”感觉 | 使用时刻 → 用户动作 → 拥有后的具体结果 | 第一人称或近距离使用瞬间、触感/握持/穿戴 |
| `emotion` | 功能正确但没有记忆点 | 原有情绪 → 商品介入 → 情绪变化 | 尴尬解除、安心、从容、愉悦、期待 |
| `personification` | 商品缺少亲近感和品牌声音 | 商品人格 → 一句对话 → 用户关系 | 商品仍是实物，不加脸；用文案口吻建立交流 |
| `identity_signal` | 用户买的不只是功能，而是表达自己 | 选择标准 → 理想自我 → 身份短句 | 编辑感、审美取向、生活方式和社交表达 |

整套规则：

- 八张营销图至少覆盖四种模式；`fab_value` 必须至少一张。
- 有已验证使用关系时，`scene_ownership` 至少一张。
- `personification` 默认最多一张；不适合的严肃、危险或受监管商品不使用。
- `identity_signal` 默认最多两张，且不能靠虚构阶层、性别、种族或经济能力完成。
- 同一模式可以重复，但购买任务、用户张力、画面瞬间和文案句式必须不同；任一模式不得超过三张。
- 白底图不进入这五种策略，不新增文字。

## 5. N5 目标契约

在现有 `SLOT_PLAN_SCHEMA` 中新增一个严格对象 `creative_strategy`，不删除已有字段：

```json
{
  "mode": "scene_ownership",
  "source_fact_refs": ["fact_12"],
  "user_job": "在外出用餐时快速取用整套餐具",
  "consumer_tension": "餐具散落、临时找不到或显得凌乱",
  "feature": "餐具和收纳盒组成完整套装",
  "advantage": "取用和收纳位置明确",
  "consumer_benefit": "打开餐包即可从容开始用餐",
  "mental_simulation": "午休时打开收纳盒，餐具已经整齐就位",
  "emotional_shift": "从匆忙凌乱到从容讲究",
  "product_voice": "今天这顿，我陪你慢慢吃",
  "identity_signal": "认真对待每一顿饭的人",
  "selection_reason": "该槽负责建立使用代入感，且有可见收纳关系支持"
}
```

规则：未使用的策略字段输出空字符串，不能填无依据内容；`source_fact_refs` 必须存在且允许 `scene_planning` 或 `consumer_copy`。现有 `copy_intent` 保留为给 N6 的一句任务摘要，不再承担完整推理。

### N5 System Prompt 必须包含的执行段

```text
你不是商品说明书写手。先把可引用事实翻译成消费者结果，再设计画面。

对每个槽位依次完成：
1. 写清用户正在完成的任务和当前阻力；
2. 从 fact_ledger 选择能够证明的事实；
3. 分别构思 FAB价值、场景占有、情绪、拟人、身份表达候选角度；
4. 选择最适合当前购买任务的一种，其他候选不输出；
5. 把选中角度转成一个可被摄影表达的瞬间，而不是抽象形容词；
6. 写 copy_intent，只描述最终短文案要让用户想到什么，不直接写成品文案；
7. 与其余槽位比较，消除重复购买问题、重复场景、重复情绪和重复句式。

禁止使用没有当前商品证据的“高品质、品质生活、轻松便携、理想之选、
开启美好生活、为你而生、everyday essential、premium quality、perfect for every moment”等空泛结论。
```

## 6. N6 文案创作与图片 Prompt

### 6.1 文案生成顺序

1. 读取 `creative_strategy` 和允许进入消费者文案的事实。
2. 在目标语言中静默生成三个不同句式候选，不先写中文再逐字翻译。
3. 按相关性、具体性、画面感、情绪/身份强度、事实可信度、自然度、移动端可读性评分。
4. 选择总分最高且事实可信度合格的一组；候选和推理不进入图片 Prompt。
5. 输出一行主标题、可选一行副标题、可选一个短标注；最多三行。
6. 生成语义回译用于 N7 检查，不显示在图片上。

### 6.2 `localized_copy` 目标结构

```json
{
  "language": "vi-VN",
  "lines": ["Mở hộp là sẵn sàng", "Gọn gàng cho từng bữa ăn"],
  "back_translation": "打开盒子即可使用；每顿饭都整齐有序",
  "strategy_mode": "scene_ownership",
  "source_fact_refs": ["fact_12"],
  "source_inference_refs": [],
  "quality": {
    "relevance": 94,
    "specificity": 91,
    "imagery": 90,
    "naturalness": 93,
    "truthfulness": 100,
    "mobile_readability": 95,
    "generic_phrase_hits": []
  }
}
```

### 6.3 英文图片 Prompt 固定六段

1. 参考图角色、商品家族、目标外观、数量和不可变化项。
2. 当前购买任务、消费者结果和唯一主要动作。
3. 唯一主场景、人物/宠物关系、构图、镜头、主体占比和道具。
4. Style DNA 的抽象光线、色彩、材质、层次、版式与摄影方向。
5. 用引号逐行写入冻结的目标语言文案，规定字体层级、位置、安全区和移动端可读性。
6. 合并排除项：不增加其他文字、Logo、平台标识、虚假 claims、额外商品部件或源风格中的可识别内容。

最终 Prompt 必须用英文控制画面；目标语言文案原样保留。OpenAI 指南中的多图索引、明确构图/动作、逐字引用文字和“改变什么/保持什么”原则用于图片执行；APIMart 接口参数仍以 APIMart 中文文档和账户契约为准。

## 7. N7 质量与失败策略

N7 接收结构化 `creative_strategy`、`localized_copy`、`visible_text_lines` 和最终 Prompt，先由后端做确定性检查，再由 DeepSeek 做语义检查。

确定性检查：

- `localized_copy.lines == visible_text_lines`，且每行在最终 Prompt 中恰好出现一次。
- 文字语言与市场映射一致；禁字模板必须为零行。
- 所有 `source_fact_refs` 存在并允许相应用途。
- 最终 Prompt 不超过 3500 字符，只有一个主场景和一个主动作。
- 同套图至少四种策略，FAB 至少一次；重复签名、重复文案和重复场景触发一次 N5/N6 自动重写。

语义检查：

- 文案是否自然、具体、符合当前场景，是否像机器直译。
- FAB 的 Benefit 是否真的由 Feature/Advantage 支持。
- 场景占有是否让用户能想象具体动作，不是空泛愿望。
- 情绪、拟人、身份表达是否与商品和目标消费者相关。
- 是否出现虚构性能、价格、认证、疗效、绝对效果或歧视性身份暗示。

低创意、空泛或重复先自动重写当前槽一次，不向员工显示技术错误；重写仍失败则只阻断当前商品并显示“营销文案准备失败，请重试”。平台硬规则、事实幻觉、引用失效或版本过期直接阻断。N7 的 `pass` 只允许提交图片，不等于图片审核通过。

## 8. 模型参数

节点使用同一个 APIMart `deepseek-v4-pro`，但不能共用同一个创造温度：

| 节点 | 温度 | 原因 |
| --- | ---: | --- |
| N2 | 0.3 | 身份归并稳定优先 |
| N3 | 0.2 | 事实和风险分类稳定优先 |
| N4 | 0.4 | 白底编译需要准确，不需要发散 |
| N5 | 1.6 | 购买角度、场景和文案意图需要创意发散 |
| N6 | 0.9 | 保留语言自然度，同时减少文案漂移 |
| N7 | 0.2 | 审查必须稳定可复现 |
| N8 | 0.4 | 修改范围必须收敛 |
| N9 | 0.2 | 简化必须保留原意 |

温度必须进入 PromptVersion/节点快照。不得给视觉模型或图片模型套用该表。

## 9. 名称缺失与多图处理

- 员工或 ERP 有名称：名称作为确认线索，但不能证明材质、功能和参数。
- 名称为空、图片可识别：N2 填入通用而具体的商品名称，例如“便携餐具套装”，继续 N3–N7。
- 名称不稳定但有可见商品：保留通用品类名称；文案只用已观察结构、外观和低风险使用关系，不因名称置信度低阻断。
- 同一卡多图：N1 全部观察，N2 区分角度与颜色/款式；N5 的白底/款式总览覆盖全部目标外观，其他槽位按购买任务选择外观子集，整套必须覆盖全部外观。
- 只有全部图片为空白、损坏、无商品或完全不可辨认时，当前商品才需要员工换图。

## 10. Style DNA 使用边界

用户提供的 `Sunlit Coastal Product Blitz` 示例值得复用的是结构，不是内容：

- 复用：风格锚点、源内容排除、画面拆解、构图、字体、色彩、摄影方向、设计规则、正向/反向约束。
- 不复用：原商品、品牌、人物、原文案、徽章文字、故事、地标、可识别版式和受版权保护的具体表达。
- N5 用 Style DNA 选择画面心理、商业密度和场景气质；N6 把它编译成可执行英文摄影指令；N7 检查源内容隔离。
- Style DNA 不能给事实台账增加商品卖点，也不能覆盖商品身份和平台硬规则。

## 11. 质量验收

用家居厨卫、宠物、婴幼儿、穿戴、美妆、工具/电器六类测试商品，各生成一套非付费 N5/N6 结构结果，共 48 个营销槽：

- 每套至少四种策略、FAB 至少一次、personification 不超过一次。
- 重复“购买任务 + 策略 + 场景 + 动作 + 构图”签名为 0。
- 无效事实引用、虚构参数和高风险 claim 为 0。
- 目标语言、冻结文字和最终 Prompt 逐字不一致为 0。
- 空泛模板文案命中为 0；至少 42/48 个槽位的相关性、具体性、自然度和事实可信度均不低于 85。
- 一套真实 1+8 付费验收中，运营对“商品准确、场景差异、文案吸引力、文字自然、整体可用”五项分别评分；任一项低于 4/5 不发布 3.1.0。
