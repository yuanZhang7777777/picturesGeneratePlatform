# Prompt OS 3.2 节点与工作流设计

日期：2026-08-02

状态：设计交接；等待 GPT-5.5 执行 Agent 实现

目标版本：`3.2.0`

## 1. 本轮要解决什么

当前问题不只是“Prompt 短”，而是链路没有把商品、图片、文案、场景、进度和失败边界串成一个稳定生产系统：

- 员工点击预备生成后，看不到真正的节点进度、Prompt 逐槽加载和并发状态。
- N1/N2 的内部字段错误会直接变成员工可见错误，例如 `image_role`、`visible product identity`、`string`。
- 商品卡拖拽范围过大，员工想滚动或点击预览时会误拖动。
- 同一卡多图到底是角度、颜色、款式还是包装，没有统一变量传给 N5/N6/N7。
- 生成按钮离商品列表太远，长列表操作成本高。
- Prompt 文案缺少“把商品事实翻译成购买冲动”的稳定方法。

3.2 的原则：少加东西，补通链路。继续复用现有 `ClusterAsset`、`analysis_snapshot`、`PromptVersion`、现有 API、TanStack Query 和 dnd-kit；不新增表、前端依赖、Redis、WebSocket 或消息队列。

## 2. 员工真实工作流

### 2.1 导入后整理

1. 员工上传图片/文件夹或输入 ERP SKU。
2. 点击“导入后整理”。
3. 系统只创建商品卡和素材，不调用任何 AI。
4. 每张图片默认一个商品卡。
5. 员工可拖缩略图把图片并入另一商品卡；被拖空且无历史的卡自动消失。
6. 员工可填商品名称、国家、平台、补充信息、单品风格提示词。

整理模式的核心边界：拖拽、排序、改名、改国家都只标记“需要重新预备”，不得自动调用 N1–N7。

### 2.2 预备生成

1. 员工勾选商品，点击常驻按钮“预备生成选中商品”。
2. 后端按商品并发执行 N1–N7；一个商品失败不影响其他商品。
3. 前端立即显示脉冲进度条和当前阶段：`识别图片 → 合并身份 → 整理事实 → 白底提示词 → 营销策划 → 逐张 Prompt → 规则检查 → 预备完成`。
4. Prompt 槽位生成一个显示一个；不要等 9 个全完成才出现。
5. 只有全部图片都无法确认有效商品，才要求员工换图或补充信息。

### 2.3 正式生成

1. 员工点击“正式生成选中商品”。
2. 如果当前商品已有未过期的 N7 通过 PromptVersion，直接进入白底图生成。
3. 如果 Prompt 缺失或因图片/排序/名称/国家/平台/风格变化过期，后端返回 `preparing` 并自动补跑 N1–N7，成功后继续生成。
4. 白底图先完成；后续 8 张营销图才提交。
5. 营销图失败只重做失败项；成功图、历史 Prompt、审核记录不覆盖。

自动出图入口等同于“导入后立即对本次导入商品执行预备生成，再正式生成”。它不跳过 N1–N7。

## 3. 工作台 UI 结构

### 3.1 顶部配置

顶部只保留一行项目级配置：

```text
项目名 | 平台 | 国家 | 比例 | 分辨率 | 项目风格提示词
```

- 平台中文按钮：`通用电商 / Shopee 虾皮 / TikTok Shop`。
- 国家中文选择：默认 `东南亚通用`，常用项包括越南、泰国、菲律宾、马来西亚、新加坡、印度尼西亚；更多国家用搜索面板。
- 比例和分辨率分开选，不合并。
- 项目风格提示词是可调整大小的小输入框，参与 8 张营销图策划，不参与白底图。

### 3.2 常驻导入区

图片/文件夹和 ERP SKU 同屏，不做抽屉，不做隐藏页签。

- 图片区：拖入区 + “选择图片/文件夹”按钮；按钮内部调用两个原生 input。
- SKU 区：文本框 + “加载 SKU”按钮 + “导入后整理 / 导入并自动出图”。
- 已导入过的图片和 SKU 不重复追加；成功项清掉，失败项保留。

### 3.3 商品卡

商品卡一行尽量 5 个左右；1920px 可 5–6 个，普通笔记本 4–5 个。

卡片结构：

```text
完整大图预览（object-contain）
横向真实缩略图：1 / 2 / 3 ...，只溢出时滚动
商品名称输入
平台、国家
补充信息小输入
单品风格折叠输入
状态、选择框、查看详情
```

交互规则：

- 点击缩略图：只切换大图预览，不改变主参考。
- 拖缩略图排序：拖到第一位才改变主参考，并使旧预备结果过期。
- 只有缩略图区域可以发起拖拽；卡片其他区域不拖，避免滚动误操作。
- 拖缩略图到另一商品卡：合并进目标卡，共同生成一套图。
- 拖缩略图到空白区域：拆成新商品卡。
- 不显示“多图关系”下拉框，不要求员工判断角度/颜色/款式。

### 3.4 侧浮层

点击“查看详情”打开右侧固定浮层，不改变商品网格布局，不挤占商品卡。

左侧显示并可直接编辑：

- 商品名称
- 平台
- 国家
- 补充信息
- 单品风格提示词
- 商品身份卡文本
- 参考缩略图排序

右侧显示 1+8 Prompt：

- 不显示生成图预览，因为预备阶段还没有生成图。
- 每槽显示中文图名、这张图解决的购买问题、可见文案、最终英文图片 Prompt。
- Prompt 生成中时每槽显示占位、脉冲条和当前节点。
- 员工可直接编辑 Prompt；编辑值就是保存值，不再要求额外“保存修改”按钮。
- 提供“重新生成这一套 Prompt”，只重跑 N5–N7，不立即生图。

## 4. 多图商品的统一解释

一个商品卡是一套图生产单元，不等于一个单色 SKU。

卡内图片可能是：

- 同一外观的多个角度。
- 不同颜色。
- 不同规格。
- 不同款式组合。
- 包装、配件、细节。

设计决定：

1. 第一张图片是主参考，决定优先抠取和保持的商品主体。
2. N1 逐张分析全部图片。
3. N2 输出共享身份锁和 `target_appearances`。
4. 相同外观多角度归为同一 appearance。
5. 不同颜色、规格、款式保留为多个 appearance。
6. 白底图和款式总览必须覆盖全部 appearance。
7. 其他营销图可以展示子集，但整套 1+8 必须覆盖全部 appearance。
8. 如果员工要每个颜色/款式各自出一套图，就不要合并，保持多个商品卡。

## 6. 九节点真实设计

### N1 逐图观察

- 模型：`gpt-5-nano-2025-08-07`
- 输入：单张我方图片、员工/ERP 名称、已填补充信息。
- 输出：图片是否有商品、候选名称、可见结构、颜色、数量、包装/配件/细节、使用关系、图片质量。
- 失败边界：单图失败只标记该图；其他图继续。`image_role` 同义词内部归一化，不给员工看。

### N2 身份归并

- 模型：`deepseek-v4-pro`
- 输入：当前卡全部 N1 结果、图片排序、员工/ERP 名称。
- 输出：`product_family`、商品显示名、`shared_identity_lock`、`target_appearances`、图文冲突。
- 失败边界：只有全部图片无有效商品时阻断。低置信名称不阻断；名称为空时生成通用但具体的商品名。

### N3 事实台账

- 模型：`deepseek-v4-pro`
- 输入：N2、员工补充、项目/单品风格。
- 输出：confirmed/observed/inferred 事实、证据、风险、允许用途。
- 失败边界：高风险 claim 不进入文案；普通缺失不阻断。

### N4 白底编译

- 模型：`deepseek-v4-pro`
- 输入：身份锁、全部 appearance、事实、白底规则。
- 输出：英文白底 Prompt、最少参考图、全部 appearance 覆盖。
- 失败边界：无合格参考图、身份锁无法建立、平台硬规则冲突。

### N5 营销导演

- 模型：`deepseek-v4-pro`
- 输入：N2/N3、目标消费者、8 个槽位、国家语言、项目/单品风格、Style DNA。
- 输出：每槽购买任务、`creative_strategy`、场景、动作、构图、外观覆盖、文案意图。
- 核心算法：先把商品事实转成消费者结果，再从五种策略中选最适合的一种。

五种策略：

1. FAB 价值翻译：功能 → 优势 → 用户收益。
2. 场景占有：让用户想象自己正在使用。
3. 情绪触发：从尴尬、麻烦、不安转为从容、安心、愉悦。
4. 拟人表达：让商品用一句自然口吻和消费者说话。
5. 身份表达：让产品代表审美、品位或生活方式。

N5 不直接写最终上图文案；它写“这张图要让用户产生什么感觉”。

### N6 本地化单槽编译

- 模型：`deepseek-v4-pro`
- 输入：单槽 N5、事实、身份锁、国家语言、规则、参考图计划。
- 输出：目标语言可见文案、回译、自评分、英文 `gpt-image-2` Prompt。
- 规则：画面控制用英文；需要上图的文字保持目标国家语言，逐字锁定，不让图片模型翻译或改写。
- Prompt 结构：商品身份与参考图 → 购买任务和动作 → 主场景/构图/光线/道具 → 冻结文案 → 禁止项。

### N7 生成前闸门

- 执行器：确定性规则 + `deepseek-v4-pro` 语义补充。
- 输入：N6 Prompt、文案、事实引用、规则、参考图、版本指纹。
- 输出：pass/block、硬阻断、警告、可自动重写项。
- 低质量文案、重复场景：自动重写一次，不暴露技术错误。
- 事实幻觉、平台硬规则、文字锁不一致、版本过期：阻断。

### N8 修改导演

- 输入：圈选区域、问题标签、文字说明、原图 Prompt、身份锁。
- 输出：只改圈选区域的差量 Prompt。
- 不改变圈外商品身份，不绕过 N7。

### N9 失败简化

- 输入：Prompt 复杂度失败或允许重写的安全拒绝。
- 输出：更短但事实等价的 Prompt。
- 网络、限流、余额、权限、提交未知不走 N9。

## 7. 员工可见错误

员工只看到能行动的错误：

| 后端真实原因 | 员工看到 |
| --- | --- |
| 全部图片空白/无商品 | `未识别到商品，请换一张更清晰的商品图` |
| 单图损坏/格式错误 | `这张图片无法读取，请重新上传` |
| ERP 图片下载失败 | `SKU 图片获取失败，可重试或手动上传` |
| 员工名称与图片明显冲突 | `商品名称和图片可能不一致，请修改名称或换图` |
| Schema/JSON/枚举/占位 string | `系统识别异常，请重试预备生成` |
| APIMart/网络/限流 | `出图服务暂时繁忙，请稍后重试` |
| 平台硬规则 | `当前图文不符合平台规则，请修改 Prompt` |

不得把 `image_role`、`visible product identity`、`N2 may only...`、`string`、JSON Schema 等字段暴露给员工。

## 8. 文案设计方法

用户提供的视频核心可以归纳为一句：文案不是列卖点，而是把商品价值翻译成用户价值和购买标准。

N5/N6 必须这样写：

1. 先拿事实：这件商品真实可见什么。
2. 转 FAB：这个事实带来什么优势，用户得到什么结果。
3. 找场景：用户在哪一刻会需要这个结果。
4. 找情绪：之前的麻烦/尴尬/不安是什么，商品介入后变成什么。
5. 找拟人：如果商品对用户说一句话，它会怎么说。
6. 找身份：买它的人想表达什么审美、品位或生活方式。
7. 每张图只选一个最强角度，不堆满。

禁用空泛成品话术：`品质生活`、`轻松便携`、`理想之选`、`高级感`、`perfect for every moment`、`premium quality`，除非它们后面有当前商品事实支撑并被改写得具体。

## 9. Style DNA 使用

用户给的 `Sunlit Coastal Product Blitz` 样例要学习的是结构：

- 风格锚点：必须可见的摄影/设计特征。
- 避免列表：不能复刻的源内容。
- 视觉拆解：构图、主体、镜头、字体、色彩、光线、材质。
- 设计规则：主次层级、版式密度、文字系统、道具边界。
- Prompt 模板：变量化，不写死原商品。

应用到本平台：

- 项目/单品风格提示词进入 N5/N6。
- 竞品图只提炼 Style DNA，不进生成参考。
- Style DNA 可以影响光线、色彩、构图、版式密度和摄影风格。
- Style DNA 不能新增商品事实、不能复刻品牌/版式/文案/人物。

## 10. 验收口径

实现完成后必须覆盖：

1. 导入后整理零 AI。
2. 预备生成多商品并发，逐商品逐节点进度可见。
3. 点击缩略图切换大图；拖缩略图排序才改变主参考。
4. 跨卡拖缩略图合并；空白拆分；卡片其他区域不误拖。
5. 同一卡多颜色/款式输出多个 `target_appearances`。
6. 白底和款式总览覆盖全部外观。
7. 8 张营销图至少四种策略，FAB 至少一张，重复场景签名为 0。
8. 目标语言文案自然、无歧义、逐字锁定在英文图像 Prompt 中。
9. 内部技术错误不展示给员工。
10. 无合格 N7 PromptVersion 时不得直接创建付费 Generation。
