# Prompt OS 3.4 节点与执行设计

日期：2026-08-02
状态：当前推荐执行基线，等待 GPT-5.5 实施
目标版本：`3.4.0`

## 1. 设计结论

3.4 不再增加新节点。它把现有 N1–N9 变成一条稳定链路：

```text
导入后整理：只保存素材和商品卡，零 AI
预备生成：N1–N7，生成商品身份、事实台账、1+8 Prompt，不生图
正式生成：缺 Prompt 或过期时自动跑 N1–N7，通过 N7 后生图
导入并自动出图：导入后直接走预备 + 正式生成
```

一个商品卡只产出一套 `1 张白底标准图 + 8 张营销图`。卡内多张图片可以是角度、颜色、规格、款式、包装、配件或细节；员工不再维护“多图关系”。第一张图片是主参考，点击缩略图只切换预览，拖动排序到第一位才改变主参考。

国家/站点只影响语言、平台规则和禁用内容，不锁死场景。场景由商品事实、消费者任务、项目/单品风格提示词、Style DNA 和营销策略共同决定。

## 2. 商品卡多图规则

默认：每张上传图片创建一个商品卡。
合并：把图片拖入同一卡，表示这些图片共同定义一套图。
拆分：把缩略图拖到空白区，拆成新商品卡。
排序：横向缩略图拖动排序，第一张为主参考。

N1 分析卡内全部图片。N2 输出两层结果：

- `product_family`：同一卡共同商品家族，例如“便携餐具套装”。
- `target_appearances`：要覆盖的目标外观。它可以是同外观多角度，也可以是粉色款、黑色款、大号、小号、套装包装、配件证据。

白底图和款式/内容总览必须覆盖全部 `target_appearances`。其余营销图可以只展示部分外观，但 1+8 整套必须覆盖全部外观。APIMart GPT Image 2 当前支持最多 16 张参考图，但生产链路不默认塞满；N6 按槽位选择“白底图 + 必要的最少我方参考图”，避免源图背景和构图把营销图拖成重复图。

## 3. 触发和状态

商品状态只给员工展示业务含义，不展示内部字段：

```text
待整理 → 识别图片 → 合并商品身份 → 整理事实 → 白底 Prompt → 套图策划
→ 单图 Prompt 1/8 ... 8/8 → 规则检查 → 预备完成
→ 白底生成 → 营销图生成 x/8 → 待审核 → 已完成
```

整理模式导入后停在 `待整理`，不调用 APIMart。
预备生成要并发处理选中商品，商品卡立即显示脉冲进度条。
正式生成如果没有合格 Prompt，先自动预备；预备成功的商品继续生图，预备失败的商品只失败自己。
Prompt 槽位生成一个就展示一个，不等九个全完成。

## 4. 变量总线

下游不重新猜图片关系，只消费 N2/N3 给出的变量：

```json

  "display_name": "木质餐具套装",
  "primary_asset_id": "asset_1",
  "supporting_asset_ids": ["asset_2", "asset_3"],
  "target_appearances": [
    {
      "appearance_id": "appearance.001",
      "label": "浅木色套装",
      "asset_ids": ["asset_1", "asset_2"],
      "visible_traits": ["浅木色", "筷子和勺子", "收纳盒"],
      "role": "main"
    },
    {
      "appearance_id": "appearance.002",
      "label": "深色款套装",
      "asset_ids": ["asset_3"],
      "visible_traits": ["深色手柄", "同类便携套装"],

    "must_keep": ["便携餐具套装", "筷子与勺子关系", "收纳盒"],
    "must_not_add": ["未证实品牌", "未证实环保认证", "未提供具体材质认证"]
```

手填商品名和补充资料是 `confirmed`，AI 不覆盖。空商品名由 N2 补全并标记“AI 识别，可修改”。`string`、枚举差异、JSON 错误、`image_role` 不合预期属于系统问题，不直接展示给员工。

## 5. 九节点职责

| 节点 | 模型/温度 | 输入 | 输出 | 阻断条件 |
| --- | --- | --- | --- | --- |
| N1 逐图观察 | `gpt-5-nano-2025-08-07` | 单张我方图、名称、补充资料 | 可见商品、结构、颜色、数量、包装、配件、人物/道具关系 | 单图坏只标记坏图；全部图都无商品才阻断 |
| N2 身份归并 | `deepseek-v4-pro` / 0.3 | 全部 N1、图片顺序、人工/ERP 名称 | `product_family`、显示名、身份锁、`target_appearances`、主/辅参考 | 全部无有效商品，或名称与图片核心冲突 |
| N3 事实台账 | `deepseek-v4-pro` / 0.2 | N2、员工补充、ERP 名称、规则上下文 | `confirmed/observed/inferred`、风险、用途 | 高风险推断不得进文案 |
| N4 白底编译 | `deepseek-v4-pro` / 0.4 | 身份锁、全部外观、白底规则 | 英文白底 Prompt、参考图计划 | 无我方参考图或白底规则冲突 |
| N5 营销导演 | `deepseek-v4-pro` / 1.6 | N2/N3、8 槽、平台、国家、风格、Style DNA | 每槽购买任务、策略、场景、动作、构图、外观覆盖 | 策略/场景重复先自动重写一次 |
| N6 单槽编译 | `deepseek-v4-pro` / 0.9 | 单槽 N5、语言、规则、事实、参考图计划 | 目标语言可见文案、回译、自评分、英文图片 Prompt | 文案语言/含义/文字锁错误先重写一次 |
| N7 规则闸门 | 确定性规则 + `deepseek-v4-pro` / 0.2 | N6、事实引用、规则、参考图、版本指纹 | pass/block、硬阻断、警告、可重写原因 | 硬规则、事实幻觉、竞品参考、版本过期直接阻断 |
| N8 修改导演 | `deepseek-v4-pro` / 0.4 | 圈选、标签、原 Prompt、身份锁 | 只改目标区域的差量 Prompt | 改动违反身份锁或硬规则 |
| N9 失败简化 | `deepseek-v4-pro` / 0.2 | Prompt 复杂度/允许重写的安全失败 | 更短但事实等价 Prompt | 网络、余额、限流、未知提交状态不走 N9 |

## 6. 营销文案方法

N5 必须把商品事实翻译成用户购买冲动。每个营销槽只选一个主策略，避免堆满：

1. `fab_value`：事实 → 优势 → 用户收益。
2. `scene_ownership`：让用户脑中出现“我正在用它”的画面。
3. `emotion`：从尴尬、麻烦、不安转为安心、轻松、体面。
4. `personification`：让商品用一句自然话跟消费者说话，默认最多一张。
5. `identity_signal`：让产品代表审美、身份、生活方式或选择标准。

八张营销图至少覆盖四种策略，FAB 至少一张。禁止空泛词和万能广告话：`品质生活`、`高级感`、`理想之选`、`premium quality`、`perfect for every moment`。没有商品名也能生成：N1/N2 先识别商品家族，N3 建事实台账，N5 再按事实写购买任务。

## 7. N5 到 N6 的标准槽位

默认 1+8：

1. 标准白底产品图。
2. 第二视角 / 结构关系图。
3. 核心卖点图。
4. 商品细节图。
5. 功能说明图。
6. 使用场景图。
7. 模特 / 比例 / 适配图。
8. 尺寸 / 包装 / 内容物图。
9. 购买收尾 / 场景体验图。

槽位名称给员工显示中文；最终 Prompt 可以英文。N5 输出的是创意 Brief，不是最终生图 Prompt：

```json
{
  "slot_order": 5,
  "chinese_slot_name": "功能说明图",
  "appearance_ids": ["appearance.001"],
  "decision_task": "让用户理解为什么适合通勤午餐后收纳",
  "creative_strategy": {
    "mode": "scene_ownership",
    "fact_refs": ["fact.storage.001"],
    "feature": "便携收纳盒",
    "advantage": "餐后能单独收回",
    "consumer_benefit": "不用担心弄脏包内物品",
    "mental_simulation": "办公室午餐后顺手放回盒子",
    "emotional_shift": "从凌乱变成安心整洁",
    "product_voice": "",

  },
  "scene_brief": {

```

## 8. 可见文字和英文生图 Prompt

N6 直接用目标语言创作文案，不走中文逐字翻译。每槽最多三行，每行短、自然、无歧义。N6 保存：

- `localized_copy.lines`：最终图片要显示的文字。
- `back_translation`：回译检查意思是否准确。
- `copy_quality`：自然度、场景匹配、事实安全。
- `final_english_image_prompt`：给 `gpt-image-2` 的英文控制指令。

最终英文 Prompt 必须逐字锁定可见文案：

```text
Visible text: render exactly these lines, with no translation, no extra words, and no spelling changes:
"{line_1}"
"{line_2}"
```

N7 再检查每一行是否在最终 Prompt 中精确出现一次。缺字、多字、被翻译、乱码、额外随机字都阻断。文案空泛或重复时只重写当前槽一次，不把内部错误暴露给员工。

## 9. Style DNA 使用

用户给的优秀 Prompt 只学习结构，不复制内容。Style DNA 字段：

```json
{
  "style_anchors": [],
  "source_content_to_avoid": [],
  "composition_logic": "",
  "subject_placement": "",
  "typography_system": "",
  "color_behavior": "",
  "texture_and_lighting": "",
  "design_rules": [],
  "negative_prompt": []
}
```

Style DNA 只能影响光线、色彩、构图、版式密度、字体气质、道具风格和摄影语言。不能新增商品事实，不能复刻竞品品牌、原文案、人物、包装、Logo、独特版式或源故事。

## 10. 员工错误文案

| 内部原因 | 员工看到 |
| --- | --- |
| 全部图片空白、风景、无商品 | `未识别到商品，请换一张更清晰的商品图` |
| 部分图片坏了 | `部分图片无法读取，可删除或重新上传` |
| N1/N2 Schema、枚举、JSON、`image_role`、`string` | `系统识别异常，请重试预备生成` |
| 名称与图片明显冲突 | `商品名称和图片可能不一致，请修改名称或换图` |
| 文案空泛、重复、语言不自然 | 不展示，系统自动重写当前槽一次 |
| 事实幻觉或平台硬规则 | `当前图文不符合平台规则或商品事实，请修改 Prompt` |
| APIMart 限流/网络 | `出图服务暂时繁忙，请稍后重试` |
| 登录/ERP Token 过期 | 直接跳登录页，不要求用户再点一次退出 |

## 11. 实施验收

- 导入后整理零 AI。
- 单图、多角度、多颜色/多款式都能预备完成。
- `image_role`、`string`、Schema 错误不污染商品名和员工界面。
- 商品卡多图排序后第一张成为主参考，并使旧预备结果失效。
- N5 八槽至少四种策略、FAB 至少一张，重复场景签名为 0。
- N6 目标语言文案逐字锁进英文 Prompt。
- N7 无通过快照时不得创建付费 Generation。
- 白底失败不生成营销图；营销失败只重做失败项。
- 最终图人工审核通过后才可导出。
