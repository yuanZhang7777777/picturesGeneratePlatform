# Prompt OS 商品出图平台实施计划

本计划将 2026-07-29 产品方案落到可运行的内部假模式版本。真实 APIMart、OSS、HTTPS 与生产部署只在契约测试、服务器 Secret 配置和发布门禁通过后启用。

## Task 1：领域模型与 Prompt OS

- 扩展项目的市场、模板、尺寸和分辨率选择，并保留规则/模板快照；所有模板第 1 槽固定为标准白底产品主图，且同一商品同一模板的后续槽位必须等待该图技术完成。
- 把 Prompt 变为结构化、版本化资产；实现商品事实、身份锁、消费者/模特、Style DNA、营销套图和单槽位编译器。
- 先实现 `gpt-5-nano-2025-08-07` 到 `VisualFactPacket` 的 Schema 校验与隔离测试；只允许已证实商品事实进入生成指令，竞品图片的抽象策略不得进入参考图数组、`gpt-image-2` 或生产 Prompt。
- 先写模型/编译器测试，再写最小实现和迁移。

## Task 2：审核、修改版本与安全交付 API

- 为生成图增加人工通过、请求修改、问题标签、相对坐标圈选和版本差量。
- 请求修改创建新 attempt，不覆盖原结果；失败重试仍只适用于技术失败。
- 提供权限保护的媒体读取、审核操作、批量导出已通过版本和实时快照数据。
- 先写 API/服务测试，再写最小实现和迁移。

## Task 3：React 运营工作台

- 创建 React + TypeScript + Vite 前端，使用 React Router、TanStack Query、dnd-kit 和 Tailwind。
- 完成工作台、项目新建、上传/商品分组、商品创作台、生产队列和审核中心的首个可操作版本。
- Django 继续处理 session/CSRF；前端不保存 token，不直接读取 OSS/供应商密钥。
- 先用组件/API 合同测试覆盖关键可见流程，再实现。

## Task 4：运维、规则与文档收口

- 更新 Compose/Caddy、环境变量样例、运行手册、项目状态和协作规则；将供应商 API 活跃异步任务上限固定为 500，并保持当前预览默认并发 2，直到完成原子认领、限流与 2、5、8、50、100、250、500 分级压测。
- 增加启动健康检查、假模式验收脚本、规则/模板种子数据和发布门禁说明。
- 不在仓库、文档、日志或前端写入密钥；真实服务器 Secret 写入在独立发布任务和锁保护下进行。

## 全局验收

- 一图一商品、拖拽合并多角度、全球市场可选、模板决定输出槽位。
- Prompt 结果可追溯、事实不臆造、竞品不作为生成参考、模特按消费者自动匹配。
- 仅审核通过版本可导出；圈选修改/技术失败重试均保留历史。
- 普通员工不见成本或供应商凭据；对象权限和 CSRF 持续生效。
