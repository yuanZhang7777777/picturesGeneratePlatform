# Prompt OS 3.2 Node Workflow Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** 让工作台、N1–N7、Prompt 展示和正式生成真正连成一条可用链路：整理零 AI，预备生成可见进度，正式生成自动补预备，一卡多图共同产出一套 1+8，并用更强营销文案 Prompt。

**Architecture:** 复用现有 Django/React/PromptVersion/analysis_snapshot。前端只收紧布局、拖拽触发区、进度和详情浮层；后端只补状态、变量归一化、Prompt 过期判断和 N1–N7 契约；Prompt 模板升级到 `3.2.0`，不覆盖历史版本。

**Tech Stack:** Django 5.2、React + TypeScript + Vite、TanStack Query、dnd-kit、APIMart `gpt-5-nano-2025-08-07`、`deepseek-v4-pro`、`gpt-image-2`。

## Global Constraints

- 权威设计：`docs/superpowers/specs/2026-08-02-prompt-os-3.2-node-workflow-design.md`。
- 不读取、修改、删除或提交 `docs/project/用户操作流程以及相关触发.md`。
- 不新增表、模型、Redis、WebSocket、消息队列、前端依赖或第三方文件选择器。
- 不覆盖历史 PromptVersion、Generation、审核记录、员工手填名称或已有商品设置。
- 整理导入、拖拽、排序和普通编辑不得调用 AI。
- 自动出图和正式生成缺 Prompt 时必须自动跑 N1–N7；N7 不通过不得付费生成。
- 内部字段错误不得展示给员工。
- 真实付费 1+8、OSS/ERP 真实 smoke 和 Hermes 部署必须由主 Agent 签核。
