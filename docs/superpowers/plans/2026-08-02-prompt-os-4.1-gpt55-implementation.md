# Prompt OS 4.1 GPT-5.5 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:executing-plans` task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 实现 Prompt OS 4.1：整理零 AI、正式生成自动预备、一卡多图共同生成一套 1+8、五策略营销文案、目标语言文字锁、N7 付费门禁和员工错误脱敏。

**Architecture:** 复用现有 Django、React、PromptVersion、ClusterAsset、analysis_snapshot、TanStack Query 和 dnd-kit。不新增表、依赖、Redis、WebSocket 或队列。后端统一变量总线和节点门禁；前端只展示商品卡、进度、Prompt 和可行动错误。

**Tech Stack:** Django 5.2、React + TypeScript + Vite、APIMart `gpt-5-nano-2025-08-07`、`deepseek-v4-pro`、`gpt-image-2`。

## Global Constraints

- 默认配置：`Shopee 虾皮 / 东南亚通用 / 1:1 / 1K`。
- `导入后整理` 不得调用任何 AI。
- `正式生成` 缺少当前 N7 pass Prompt 时必须自动预备并续接生成。
- 一个商品卡只产出一套 1+8；卡内全部图片共同参与。
- 第一张为主参考；点击缩略图只预览，拖动排序到第一位才改变主参考。
- 员工不维护“多图关系”；多色/多款由 N2 输出 `target_appearances`。
- 国家只在 UI 显示为“国家”，不显示 `market`；国家只控制语言/硬规则，不锁定场景。
- N2 输出 `product_family`、`shared_identity_lock`、`target_appearances`。
- 国家只控制语言、规则和禁用内容，不限制场景创意。
- N5 温度 1.6；N6 温度 1.0；N2/N3/N7 低温。
- 每个节点模板必须包含：角色与唯一职责、输入变量解释、决策规则、质量评分、输出 JSON Schema 约束、失败归一化。
- 工作台配置一行：平台、国家、比例、分辨率、项目风格提示词；比例和分辨率分开选。
- 图片/文件夹与 ERP SKU 同屏常驻；生成操作在长列表滚动时仍可见。
- 不触碰 `docs/project/用户操作流程以及相关触发.md`。
- 不打印 Secret，不覆盖历史 Prompt/生成/审核，不删除或 skip 测试。

---

## Shared Runtime Contract

Every implementation task must preserve this handoff chain:

```text
N1 owned_observations + valid_asset_ids
→ N2 product_family + shared_identity_lock + target_appearances + primary_asset_id
→ N3 fact_ledger + allowed_fact_ids
→ N4 white_prompt_version + white_reference_plan
→ N5 slot_plans + appearance_coverage_plan
→ N6 localized_copy + final_english_image_prompt + reference_plan
→ N7 n7_pass_snapshot
→ Generation
```

If a required value is missing or stale, stop that product or enqueue prepare. Do not continue with `string`, empty objects, old PromptVersion, `builtin-v1`, or a generic fallback prompt.

## Execution Rule for GPT-5.5

This plan is implementation-only. Do not create another 4.x design, do not add a new node, and do not replace the workflow with a new abstraction. If the current code conflicts with the design, change the smallest shared path that makes the code follow the 4.1 contract.

The quality target is not “tests are green”; the visible product must satisfy these runtime checks:

- N1/N2 can continue when at least one owned product image is valid.
- N5 produces a purchase reason chain, not only slot labels.
- N6 locks the target-language copy inside an English image prompt.
- N7 prevents paid generation unless the prompt, facts, references and version fingerprint still match.
- The employee UI never exposes internal model/schema field names.
- Node failures are classified before display: normalize model output first, continue when at least one valid product image exists, block only the current product for real business conflicts, and show only actionable Chinese errors.
