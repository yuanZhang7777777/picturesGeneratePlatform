# AI 商品出图平台 P0 改造实施计划

## 目标

本轮解决三个生产根因：

1. 上传必须同时支持图片、文件夹和拖拽，失败项可单独重传。
2. Prompt 生产改为可追踪的九节点 Prompt OS v2，最终指令不得覆盖身份锁、事实和平台规则。
3. 平台规则按平台、市场、店铺类型、类目、槽位和版本保存官方证据；未核实规则不得宣称自动合规。

实施状态（2026-07-30）：Tasks 1–4 已在本地代码和前端落地；后端全量 192 项、前端 45 项、Django check、迁移漂移检查、Vite build 和 diff check 已通过。浏览器真实上传、OSS/APIMart smoke 和服务器重新部署仍属于 Task 5。

## 已确认边界

- 导入入口保留“本地图片/文件夹”和“ERP SKU”两种，进入同一商品确认与 9 图生产链路。
- 默认一张图一个商品分组；拖入同一分组表示同商品补充参考，也可表示多色/多款组合。
- 默认输出为 1 张标准白底图加 8 张营销图。
- Shopee VN 普通店为特殊 9 图结构：真实上传/ERP 原图、标准白底图、7 张营销图。
- 图像理解使用 `gpt-5-nano-2025-08-07`；分析、策划、本地化和 Prompt 编译使用 `deepseek-v4-pro`；生成与圈选修订使用 `gpt-image-2`。
- 允许合理推断商品材质、功能、规格和卖点，但必须进入推断台账并在审核页展示；平台禁止的虚假价格、认证、疗效、减重、美容前后对比和站外导流等内容仍由硬规则阻断。
- 图中文字由生成模型直接生成；最多 3 行且只能使用编译器列出的文字。禁字市场自动关闭新增文字。
- 所有输出必须人工审核；只导出审核通过版本，失败和修改均保留历史。

## Task 1：上传链路

- 前端拆分“选择图片”和“选择文件夹”，支持拖放图片与嵌套文件夹。
- 用户选择素材后，再明确选择“导入并自动出图”或“导入后整理”；操作按钮不再打开文件选择器。
- 接受 JPEG、PNG、WebP 和 UTF-8 TXT；WebP 用 Pillow 转为 PNG。HEIC、GIF、PSD 返回明确拒绝原因。
- 单次业务上限为 100 张图片、20 个 TXT；浏览器按最多 50 个文件分批提交。单图 20 MiB、TXT 256 KiB。
- 上传 API 对每个文件返回 `imported` 或 `rejected`，成功项不因单个坏文件回滚或隐藏。
- TXT 按相对路径排序后合并为项目级种子风格，并先于图片识别生效。
- 认证、CSRF、OSS、超时、格式和大小错误返回脱敏、可操作的 JSON；“重试失败项”只重传失败文件。

## Task 2：平台规则与模板

- `RuleProfile.rules` 内的规则项统一为：

```json
{
  "rule_id": "tiktok.us.gallery.no_added_text",
  "market": "US",
  "seller_tier": "general",
  "category_scope": ["all"],
  "slot_scope": ["cover", "gallery"],
  "severity": "HARD_PLATFORM",
  "requirement": "...",
  "prompt_directive": "...",
  "source_url": "...",
  "source_date": "2026-06-15",
  "checked_at": "2026-07-30",
  "verification_status": "verified"
}
```

- 规则等级限定为 `HARD_PLATFORM`、`HARD_MALL`、`TECH_UPLOAD`、`ADVICE`、`UNVERIFIED`、`INTERNAL_BASELINE`。
- 项目增加 Shopee 店铺类型 `general` / `mall`，默认 `general`；TikTok Shop 不显示该字段。
- 未核实市场仍可生产：复用对应平台的官网主规则包和全局 9 图模板，界面标记 fallback，不显示该国家“官方自动合规”。
- Shopee VN 普通店和 TikTok Shop US/TW 的特殊槽位与文字策略必须有自动化测试。

## Task 3：Prompt OS v2

每个节点保存模板版本、输入快照、模型版本、严格 JSON 和结果：

1. 逐图观察：识别商品、包装、配件、人物、道具、局部、变体和无关图。
2. 身份归并：选择主参考图、最多 3 张互补图，形成商品身份锁和外观版本。
3. 推断台账：事实分为 `confirmed`、`observed`、`inferred`，保存置信度和风险。
4. 标准白底编译器：生成完整、纯白、无新增文字和水印的标准商品图。
5. 八图营销导演：从结构、细节、使用、人物/宠物、空间比例、包装包含物、本地生活方式和补充转化中选择不重复场景。
6. 本地化与单槽编译器：确定精确文案、对象关系、构图、光线、镜头、道具和禁止项。
7. 规则闸门：付费调用前检查硬规则、身份锁、语言、推断内容和参考图。
8. 修改导演：把圈选、标签和文字意见编译成只改目标区域的差量指令。
9. 失败简化器：只处理 Prompt 复杂度或内容安全拒绝；网络和限流继续使用原 Prompt。

最终图片 Prompt 不超过 3,500 字符，只包含一个主场景和一个主要动作。参考图固定为一张主图和最多三张结构补充图；营销图额外加入已经完成的白底图。

N1–N9 当前生产核心提示词版本为 `2.1.0`，使用九节点规格中的完整角色、事实边界、营销方法、规则和严格 JSON 约束。DeepSeek 节点通过 Chat Completions 的 `system` 消息接收完整模板；旧 `2.0.0` 一句摘要版本保留审计记录但退出生产。3,500 字符限制不作用于节点系统提示词。

## Task 4：Prompt 编辑与审核体验

- `POST /api/clusters/{id}/` 接受结构化 `prompts` 数组和 `expected_version`。
- 每次人工保存创建新的未使用 `PromptVersion`；已用于生成的版本永不覆盖。
- 商品确认页显示九槽策划、最终 Prompt、事实来源和推断台账。
- 审核页显示该图使用的确认事实、观察事实和推断内容；通过后才可导出。
- 圈选修改保存区域、标签、说明和差量 Prompt，不污染原图。

## Task 5：验证与发布

- 后端覆盖上传、WebP、非法混合文件、100 图加 20 TXT、Prompt 节点、规则闸门、版本历史和导出权限。
- 前端覆盖图片/文件夹/拖拽、分批上传、失败重试、Shopee 店铺类型、九槽编辑和推断台账。
- 发布前执行 Django 全量测试、迁移漂移检查、React 测试与构建、浏览器真实上传、OSS smoke、Prompt 节点 smoke 和一套真实 9 图导出。
- 六类商品共 54 张是正式付费基准；只有在六类真实商品素材齐全时执行并记录真实结果，绝不以模拟数据冒充完成。

## 多 Agent 边界

已完成的上传、Shopee、TikTok 三项只读审计作为本计划输入。实现阶段如执行器没有用户指定的 5.5 模型，不改用 5.6，由主 Agent 完成代码集成、验证、付费验收和部署。
