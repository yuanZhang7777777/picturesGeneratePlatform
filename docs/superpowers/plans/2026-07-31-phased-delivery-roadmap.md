## 1. 交付原则

后续按可实际验收的业务闭环推进，不再把前端、后端、Prompt 分别做完后才集成。

- 每阶段同时完成代码、测试、预览部署、浏览器验收和回退点。
- 未通过当前阶段门禁，不进入下一阶段，也不提前做推测性功能。
- 阶段内先冻结接口，再让文件边界不冲突的 Agent 并行。
- 旧实施计划保留为历史记录，不删除、不继续作为排期依据。
- `docs/project/用户操作流程以及相关触发.md` 不在本路线图维护范围内，不读取、不修改、不引用。

## 3. 阶段 0：冻结基线与任务重排

目标：确保后续改造可回退，停止在旧页面零散打补丁。

已完成：

- 记录当前代码、迁移、模板版本和服务器服务状态。
- 把上传预览、重复导入、选择失效、删除、ERP、空商品名、紧凑列表、项目/商品平台国家登记为新 P0。
- 冻结阶段 1 的前后端行为和 Agent 文件边界。

门禁结果：本地回归、前端构建、远端健康检查均通过；回退版本明确。

## 4. 阶段 1：批量整理工作台可用化

目标：运营能稳定完成一次导入 1–50 个商品并整理。

- 上传前、上传后都显示无文件名缩略图。
- 成功文件从待导入区移除，失败文件保留；连续导入不重复提交旧图片。
- 修复单商品取消生成无效；支持全选、取消全选、反选。
- 商品改为紧凑列表，一屏约 6–8 个；详细资料进入右侧抽屉。
- 空商品名保持空值，只显示“可不填，AI 将根据图片识别”占位提示。
- 支持删除待上传图片、已导入图片和商品。
- 无历史商品物理删除；有历史商品仅归档；生成中的商品拒绝删除。
- 保留拖拽归并、多图关系和失败项重试。

验收门禁：

- 单图、多图、文件夹连续导入无重复。
- 50 个商品可流畅选择、整理和滚动。
- 0 个商品选中时不能生成。
- 图片和商品删除符合历史保护规则。
- 后端、前端全量测试、构建和浏览器 E2E 通过。

## 5. 阶段 2：ERP 与平台/国家配置闭环

目标：两套导入入口和目标市场真正可用。

- “图片/文件夹”和“ERP SKU”作为两个一级页签。
- ERP 输入解析为 SKU 标签；成功项清除，失败项保留。
- 逐条显示 SKU 不存在、ERP 不可用、Token 过期、图片失败和 OSS 失败。
- 使用真实员工 ERP 登录和一个真实 SKU 验证商品名、图片与 OSS 归档。
- 创建项目时选择平台与目标国家；工作台顶部可修改默认平台、国家、比例和分辨率。
- 店铺类型默认普通店，仅放在“更多设置”。
- 每个商品可覆盖平台和国家，默认继承项目；覆盖只重新准备当前商品，不改写历史。
- 没有站点专用规则的国家复用平台官网主规则和全球通用模板。

数据与接口：

- 商品增加可空的 `platform_override`、`market_override`、`seller_tier_override`。
- 有效配置按“商品覆盖 → 项目默认 → 全球通用”解析。
- 增加项目设置更新、素材删除及商品删除/归档接口。
- 项目快照返回默认配置、商品覆盖和最终生效配置。

验收门禁：两种入口均能完成自动出图和导入后整理；商品市场配置影响规则、语言和模板；Shopee VN 保持“真实原图 + 白底 + 7 营销图”；真实 ERP SKU 浏览器 smoke 通过。

## 6. 阶段 3：Prompt OS 运行契约补齐

目标：生产代码真正执行 N1–N9 设计。

- N1 实际接收商品名、确认事实、图片关系和资产信息。
- N2 选择的主图和最多三张辅助图控制后续参考图数组。
- N3 保存 `confirmed / observed / inferred`、置信度和用途边界。
- N4 接收主图、辅助图、尺寸、分辨率和完整白底槽位参数。
- N5 接收平台、国家、语言、文字开关、种子风格和实际营销槽位。
- N6 每槽接收市场语言、规则、参考图计划和已完成白底图。
- N7 保留确定性硬规则，并由 DeepSeek 补充语义风险；语义模型不能取消硬阻断。
- N1–N9 发布实际 JSON Schema；非法 JSON 只修复一次，再失败只阻断当前商品。
- 最终 GPT Image 2 Prompt 不超过 3,500 字符；节点系统提示词不受此限制。

验收门禁：参考图只来自 N2 批准项；目标市场语言与禁字正确；Prompt 无未登记事实和重复场景；每个节点均有不可变输入、输出、模型和版本快照。

## 7. 阶段 4：生成、修改、审核与导出闭环

目标：每套图可修改、可审核、可交付。

- 每个商品先生成并归档标准白底图，再提交营销图。
- 白底失败不提交后续槽位；营销图失败只重做失败项。
- N8 将圈选坐标转为修订输入；供应商不支持 Mask 时使用受控标注参考图。
- 修改只改变目标区域，并创建新的 PromptVersion 与 Generation。
- N9 只处理 Prompt 复杂度和允许重写的安全失败；网络、限流沿用原 Prompt。
- 审核支持新旧版本并排、圈选、问题标签和文字意见。
- ZIP 只包含人工审核通过的版本，按商品名称与 SKU 组织，不使用源照片文件名。

质量门禁：家居厨卫、宠物、婴幼儿、穿戴、美妆、工具/电器各完成一套，共 54 张；商品身份硬错误为 0；平台硬规则命中率 100%；每套营销场景不重复；至少 5/6 套达到运营人工可用性 4/5。

## 8. 阶段 5：平台规则、竞品分析与 Prompt Lab

目标：核心生产闭环稳定后扩展专业能力。

- 完善 Shopee 与 TikTok Shop 平台主规则和有资料的国家覆盖。
- 无独立资料的国家继续复用平台官网规则，不伪造站点规则。
- 竞品图只进入 GPT-5 Nano 视觉观察并输出抽象 Style DNA。
- 竞品原图不进入 DeepSeek、GPT Image 2、商品事实或导出。
- Prompt Lab 提供节点模板、版本差异、样本回放、通过率、驳回率和回滚。
- Prompt 候选版本通过基准商品集后才可发布。

验收门禁：规则来源、版本、站点和核对日期可追溯；竞品素材隔离通过；Prompt 发布/回滚不改写历史任务。

## 9. 阶段 6：正式发布与容量提升

目标：从预览系统升级为约 100 名内部员工使用的正式系统。

- 公网入口启用员工设备可信 HTTPS，HTTP 只重定向。
- 完成 ERP 登录、Session、CSRF、对象权限和管理员权限安全验收。
- 增加任务原子认领、用户公平调度和供应商限流。
- 为上传请求增加服务端幂等键，覆盖“服务端已成功但浏览器丢失响应”后的安全重试。
- 默认每人最多两个活跃任务；无人排队时可借用空闲容量。
- APIMart 并发按 `2 → 5 → 8 → 50 → 100 → 250 → 500` 分级压测。
- 验证每日 2,000 张目标的成功率、平均耗时、失败率和费用。
- 完成数据库备份、OSS 生命周期、健康检查、脱敏日志和发布回退。
- 按 5、20、50、100 人逐级试用后扩大范围。

正式门禁：100 人权限隔离正确；每日 2,000 张容量达标；Secret 泄漏为 0；刷新、断网、重试和服务器重启不丢历史；HTTPS、备份、监控和回退演练通过。

## 10. Multi-Agent 推进规则

- 主 Agent 维护唯一规格、接口、任务状态、合并、付费验收与部署。
- 阶段 1：前端体验 Agent + 后端删除/归档 Agent。
- 阶段 2：ERP/配置 Agent + 前端市场选择 Agent。
- 阶段 3：Prompt OS Agent 主导，规则 Agent 只提供规则输入。
- 阶段 4：生成审核 Agent + QA Agent。
- 阶段 5：规则 Agent + Prompt Lab Agent。
- 阶段 6：后端性能 Agent + QA/运维 Agent。
- 不同 Agent 不编辑同一文件；每阶段结束必须提交改动范围、测试结果、浏览器证据、服务器 smoke、风险和回退点。
